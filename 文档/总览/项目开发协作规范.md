# 文档/总览/项目开发协作规范.md — 高尔夫挥杆速度应用程序

## 项目概述

Golf Swing Speed App 是一款 iPhone 应用程序，可使用设备的内置 LiDAR 扫描仪和 240 fps 摄像头测量高尔夫球杆杆头速度，无需外部硬件。它针对的是需要即时、自由挥杆速度反馈的速度训练高尔夫球手。

**状态：** 积极开发 - 第 2-4 阶段功能已完成 (V0.02.10)
**平台：** iOS（iPhone 12 Pro 及更高版本 - 需要 LiDAR）
**语言：** 斯威夫特
**用户界面框架：** SwiftUI

### 核心管道
1. **音频监听**（空闲）→ 通过嗖嗖声检测挥杆开始
2. **240fps捕捉**由音频触发→记录全摆动弧线（最少的实时处理）
3. **每帧的捕获后分析**（~240-360 帧，~4-15 秒处理）：
   - 所有帧上的 3D 身体姿势 (`VNDetectHumanBodyPose3DRequest`) 全 240fps
   - 所有帧上的球杆头检测（YOLO）+跟踪（光流+卡尔曼）
   - 使用 LiDAR 校准的 3D 位置进行速度计算
   - 全时间分辨率的真实 3D 滞后角计算
   - 释放点检测精度达到 ±4ms / ±1-2°
4. **从校准的冲击区域位置提取冲击速度**
5.速度+滞后分析结果的**音频反馈**

## 编码约定

- Swift 5.9+、iOS 17.0+ 最低部署目标
- 适用于所有 UI 的 SwiftUI，除非相机/AR 视图需要，否则没有 UIKit
- 对所有异步操作使用 async/await
- 使用 Swift 并发（参与者）来获取线程安全的传感器数据
- 尽可能优先选择值类型（结构）而不是类
- 所有内部测量均采用 SI 单位（米、秒）；转换为 mph/kmh 仅用于显示
- 相机管道使用 CMSampleBuffer → CVPixelBuffer → CIImage 流程
- 核心 ML 模型存储在 ML/ 目录中，扩展名为 .mlmodel
- 使用 #Preview 宏进行 SwiftUI 预览

## 关键技术决策

- **240fps @ 1080p** 是拍摄目标（iPhone 上可用的最大值）
- **混合跟踪：**慢帧的YOLO检测+快帧的光流+卡尔曼滤波器
- **音频触发捕获**，与连续录制相比，可减少电池/热影响
- **LiDAR 仅用于校准**（60Hz 对于 240fps 跟踪来说太慢）- 建立像素到米的比例
- **瞄准位置校准** — 当高尔夫球手处于静止状态时，结合 Apple 3D 身体姿势 + LiDAR + CV 来测量：球杆长度、杆底角、杆身平面、臂长、球位置。这些成为跟踪期间的卡尔曼滤波器约束（球杆头必须位于手腕的 Club_length 范围内，大约在挥杆平面内）
- **捕获后处理** — 所有大量分析在摆动完成后运行。无实时限制
- **自适应帧采样** - 并非所有摆动阶段都需要 240fps 分析。下杆后期 → 冲击达到全 240fps；后摆和后续动作的处理速度为 30-60 fps。两遍方法：以约 30fps 的速度快速进行相位检测，然后对关键帧进行有针对性的全面分析。处理量减少约 45%
- **未来：学习推理模型** - 当应用程序构建全面分析的挥杆数据集时，训练一个 ML 模型，该模型可以根据稀疏输入（更少的帧 + 音频 + 校准）预测速度/滞后/释放。目标：从最少的数据中获得近乎即时的结果，以完整的流程作为验证模式
- **v1 范围：球杆头速度 + 滞后角度分析** — 无球跟踪、杆面角度、旋转或其他发射监控指标
- **滞后角度检测** 通过 MediaPipe/Vision 身体姿势 + 球杆杆身跟踪。报告：滞后保持指数、释放点、冲击时轴倾斜、铸造检测
- **音频反馈系统**具有两种模式：蜂鸣模式（低延迟音调）和语音模式（AVSpeechSynthesizer）。自动路由至 AirPods/蓝牙

## 准确度目标

|版本 |目标精度|方法|
|---|---|---|
| v1.0 | ±5-8 英里/小时 |基本的帧到帧跟踪 |
| v1.1 | ±2-4 英里/小时 | + 亚像素跟踪 + 运动模糊速度估计 + 卡尔曼平滑 |
| v2.0 | ±1-3 英里/小时 | + 经过训练的 ML 模型 + 传感器融合 + 可选的反射标记 |**关键：** 1 像素位置误差 ≈ 0.6 英里/小时速度误差。对于训练使用来说，一致性比绝对准确性更重要。

**请勿使用：** AI 帧插值 (RIFE/FILM) 进行测量 - 没有新的时间信息。用于直接跟踪的 LiDAR — 60fps/256×192 不够。

## 关键：帧时序

**不保证 iPhone 240fps。**报告显示，当设置为 240fps 时，iPhone 14 Pro 的实际帧率为 162-200fps。速度计算必须使用 `CMSampleBuffer.presentationTimeStamp` 中的实际帧时间戳，切勿假设一致的 1/240 秒间隔。

## 已知的难题

1. 时速超过 100 英里时的运动模糊导致击球时杆头检测不可靠
2. 球杆头小、速度快，并且与背景的对比度通常较低
3. 球杆经过高尔夫球手身体后方时的遮挡
4. 前置摄像头角度的透视变形
5. 持续 240fps 捕捉期间的热节流
6.室外风噪声干扰音频摆动检测

## 版本控制和 Git 工作流程

### 承诺并推动政策
- **始终在研究完成、主要文档更新或功能更新之后提交并推送到 GitHub** - 始终保持远程存储库同步
- 提交消息应具有描述性，并在适用的情况下引用版本号

### 版本控制 — V0.00.00 凹凸工作流程
该项目使用三层语义版本格式：**V`MAJOR`.`MINOR`.`PATCH`**

|凹凸|格式|当 |需要批准吗？ |
|---|---|---|---|
|补丁| `0.00.XX` |小代码更改、错误修复、小调整 |否 — 自由申请 |
|次要| `0.XX.00` |更大的功能更新、重大重构、新功能 | **是的 - 在碰撞之前需要用户批准** |
|专业| `X.00.00` |重大的大型构建、重大里程碑、突破性变更 | **是的 - 在碰撞之前需要用户批准** |

- 当前版本：**V0.02.10**
- 在项目中跟踪版本并随着每个相关提交进行更新
- 轻微碰撞时补丁会重置为 00；补丁和小重置为 00 在重大碰撞
- 如果对提升水平有疑问，请在提交前询问
