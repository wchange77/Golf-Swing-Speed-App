# 高尔夫挥杆速度应用程序 — 产品要求文档

> **版本：** 1.0
> **日期：** 2026 年 3 月
> **状态：** 批准开发
> **平台：** iOS 17.0+（iPhone 12 Pro 及更高版本）

---

## 1. 执行摘要

Golf Swing Speed App 是一款免费的 iPhone 应用程序，仅使用设备的内置 LiDAR 扫描仪、240fps 摄像头和麦克风即可测量高尔夫球杆头速度并分析手腕滞后/释放，无需外部硬件。

该应用程序针对的是速度训练高尔夫球手，他们目前必须花费 300 至 25,000 美元购买专用发射监视器才能获取挥杆速度数据。一位竞争对手 (ShotVision) 尝试仅使用摄像头进行速度测量，但可靠性较差（在光线不好的情况下，精度会损失 30-50%）。我们的方法结合了 LiDAR 校准的 3D 测量、Apple 的内置 3D 身体姿势估计、音频触发捕获和自适应捕获后分析，可通过单个 iPhone 提供准确的速度测量和滞后角分析。

**核心价值主张：** 准确的杆头速度 + 抛投/滞后分析，即时、免费，可通过您口袋中的 iPhone 进行。

## 2. 产品愿景与策略

### 2.1 为什么会出现这种情况
速度训练是高尔夫教学中发展最快的领域之一。 SuperSpeed Golf、The Stack 和超速训练协议等项目要求高尔夫球​​手在每次训练中测量和跟踪数百次挥杆的杆头速度。当前选项：

|选项 |成本|便携性|速度数据|
|---|---|---|---|
|田径手 / GCQuad | 12,000 美元–25,000 美元 |低|优秀|
| Garmin R10 / 拉普索多 | $400–$700 |中等|好 |
| ShotVision（应用程序）|免费/订阅 |优秀|不可靠 |
| **我们的应用程序** | **免费/免费增值** | **优秀** | **良好（±3-5 英里/小时目标）** |

### 2.2 竞争定位
- **与 Launch 显示器相比：** 我们并不是要更换价值 2 万美元的 Trackman。当您在后院拿着速度棒进行 50 次挥杆并且只想知道您的数字时，我们就是您可以抓住的工具
- **与 ShotVision：** 相同的概念，但我们使用 LiDAR 校准（他们没有）、3D 身体姿势（他们没有）、音频触发捕获（他们没有）和 240fps 分析（他们使用标准相机速率）。我们的可靠性应该明显更高
- **与 SwingVision（网球）：** 证明这个概念是有效的。他们的创始人（前特斯拉 Autopilot）在 iPhone 上验证了仅通过摄像头进行速度跟踪。高尔夫更难（更小、更快的物体），但我们的 240fps 提供了 4 倍的时间分辨率
- **独特的优势：** LiDAR 校准、3D 滞后角分析、音频触发捕获、地址位置设备测量、自适应帧采样

### 2.3 护城河
- 在高尔夫球杆头上训练的 ML 模型随着分析的每次挥杆而改进
- LiDAR 校准是 iPhone 独有的（Android 无法复制）
- 瞄准位置设备校准（球杆长度、杆底角、挥杆平面）以竞争对手无法比拟的方式限制跟踪
- 未来学习推理模型（“教练之眼”）成为复合数据优势

## 3.目标用户### 3.1 主要：速度训练高尔夫球手
- **对象：** 业余高尔夫球手（5-25 差点）通过 SuperSpeed Golf、The Stack 或超速训练等协议进行专门的速度训练
- **需要：** 每次训练 30-100 多次挥杆时进行快速、重复的速度测量。目前没有使用任何测量或借用朋友的发射监视器
- **使用案例：**后院、练习场或室内击球区。将手机放在三脚架上，训练 15-30 分钟，然后查看速度趋势

### 3.2 次要：高尔夫教练
- **人员：** 职业教练、高尔夫教练、初级教练
- **需要：** 轻量级速度测量工具，无需在每次课程中都携带启动监视器
- **用例：** 在课程中快速检查速度。通过滞后分析向学生展示他们的选角模式

### 3.3 第三级：好奇的休闲高尔夫球手
- **对象：** 从未测量过挥杆速度的休闲高尔夫球手
- **需要：** “我实际挥杆的速度有多快？” — 一次性的好奇心或偶尔的签到
- **用例：** 在靶场，设置手机，击中几枪，查看数字

## 4. 货币化——免费增值模式

### 4.1 免费套餐
- 球杆头速度测量（冲击速度）
- 通过语音/蜂鸣声快速读出
- 基本挥杆历史（最近 50 次挥杆）
- 手动校准（点击设置）
- 音频反馈（仅限蜂鸣模式）

### 4.2 高级级别（订阅或一次性解锁 — 定价待定）
- LiDAR 自动校准与地址位置设备分析
- 滞后角分析（LRI、释放点、轴倾斜、铸造检测）
- 带有手臂/轴覆盖和颜色编码滞后可视化的挥杆重播
- 全速曲线可视化
- 无限的挥杆历史记录和会话分组
- 挥杆比较（并排）
- 语音模式音频反馈（AVSpeechSynthesizer）
- 将数据导出至 CSV
- 详细的统计和趋势跟踪
- 优先处理（自适应采样优化）

### 4.3 基本原理
核心速度测量是挂钩——自由且无摩擦。滞后分析和详细的可视化是教练和专业速度训练师愿意花钱购买的优质差异化因素，因为这些数据通常需要 3,000 美元以上的 HackMotion 传感器或 30000 美元以上的 GEARS 系统。

## 5. 功能要求 (v1)

### F1：相机捕捉系统

**优先级：** 关键 — 所有测量的基础

|要求|规格|
|---|---|
|帧率| 240fps @ 1080p（最大可用）|
|编解码器|用于高效存储的 HEVC (H.265) |
|帧时间戳 |从 `CMSampleBuffer.presentationTimeStamp` 读取 — 切勿假定间隔一致 |
|录音时长|仅在检测到的摆动期间捕获（每次摆动约 1-2 秒）|
|存储|捕获期间的临时目录，保存时移至持久存储 |
|预览 |空闲/就绪状态下显示实时摄像头画面 |
|方向|风景、后置摄像头 |

**关键限制：** 不保证 iPhone 240fps。报告显示实际速率为 162-200fps。所有速度计算必须使用每帧实际测量的时间戳。**热管理：**
- 音频触发捕捉意味着相机仅在实际摆动期间（约 1-2 秒）以 240 fps 运行
- 在摆动之间，相机预览或待机时的帧率可以降至 30 fps
- 如果设备温度超过阈值，则显示热警告
- 每次训练的预计主动捕捉时间：30 分钟的训练中总共 2-5 分钟

### F2：校准系统

**优先级：** 关键 — 精度取决于校准质量

#### F2.1：手动校准（免费套餐）
- 用户点击相机预览上的两个点
- 用户输入这些点之间的已知距离（例如球杆长度、站姿宽度）
- 应用程序计算每米像素比例因子
- 用户点击来标记撞击区域位置
- 校准存储并可重复使用，直到相机移动

#### F2.2：LiDAR 自动校准（高级）
三相校准：

**第 1 阶段 — 场景设置：**
- ARKit 会话扫描场景，识别地平面
- 建立3D世界坐标系
- 测量相机相对于地面的高度和角度

**阶段 2 — 地址位置分析：**
当高尔夫球手站在瞄准位置（静态）时，应用程序会同时捕获：
- `VNDetectHumanBodyPose3DRequest` → 17 关节 3D 骨架（肩部、肘部、手腕位置以米为单位）
- 通过 CV 模型检测球杆头 → LiDAR 提供 3D 球杆头位置的深度
- 球检测（如果有）→ 白球 CV 检测 + LiDAR 深度

导出的测量值：
|测量|计算|使用 |
|---|---|---|
|球杆长度| 3D距离：手腕→球杆头|约束卡尔曼滤波器跟踪半径 |
|躺角|轴矢量与地平面角度|自我验证（预计 56-64°）|
|轴平面|穿过脊椎、手、球杆头的平面|用于追踪的预测挥杆平面|
|臂长|肩→腕3D距离|最大回转圆弧半径约束|
|球到手的几何形状| 3D矢量|影响区域预测 |

**阶段 3 — 锁定：**
- 校准数据锁定
- 相机必须保持静止（IMU 检测运动，警告用户）
- 所有导出的测量结果都作为跟踪管道的约束传递

#### F2.3：深度布局（面部摄像头约 2-3m）
球杆头/球距离摄像机比高尔夫球手的身体更近 0.5-1.0m（球杆以底角向前延伸，以在脚之前到达地面）。在这些距离下，LiDAR 精度为 ±2-3cm。所有测量都是直接进行的——没有平面假设。

### F3：球杆头检测和跟踪

**优先级：** 关键——核心测量能力

#### F3.1：检测模型
- 在高尔夫球杆头图像上训练的自定义 YOLOv8 模型
- 基础数据集：AICaddy（6,000 多张图像）+ Roboflow 高尔夫俱乐部跟踪（6,750 张图像）
- 增强了不同速度/照明下的运动模糊球杆头图像
- 导出为 iPhone 神经引擎的 Core ML 格式
- 推理目标：A17 Pro+ 上每帧<6ms#### F3.2：跟踪管道（捕获后）
每个摆动阶段的混合方法：
1. **YOLO 检测** — 在慢帧中定位球杆头（后摆、后续挥杆）
2. **Apple Vision VNTrackObjectRequest** — 检测之间的快速硬件加速跟踪
3. **光流 (VNGenerateOpticalFlowRequest)** — 帧到帧运动向量
4. **卡尔曼滤波器**——通过模糊/遮挡预测位置，平滑轨迹
5. **校准限制** — 球杆头在手腕的 `club_length` 内，大约在 `swing_plane` 内

#### F3.3：3D 身体姿势（捕捉后）
- 每个分析帧上`VNDetectHumanBodyPose3DRequest`
- 提供高达 240fps 的 3D 手腕位置（捕获后，无实时限制）
- 手腕位置将球杆头搜索限制为`club_length`半径球体
- 17个关节：头、肩、肘、腕、脊柱、臀部、膝盖、脚踝

### F4：速度计算管道

**优先级：** 关键

#### F4.1：核心计算```For each consecutive pair of tracked frames (i, i+1):
  displacement_3d = distance(position_3d[i], position_3d[i+1])
  time_delta = timestamp[i+1] - timestamp[i]  // ACTUAL timestamps, not 1/240
  instantaneous_speed = displacement_3d / time_delta
  speed_mph = instantaneous_speed * 2.23694
```
#### F4.2：速度曲线
- 每个跟踪帧的（时间戳、速度每小时、置信度）数组
- 卡尔曼平滑以减少噪音
- 冲击速度 = 最接近校准冲击区域位置的框架处的速度

#### F4.3：补充：运动模糊速度
- 模糊条纹长度编码速度：`speed = blur_length × distance / (exposure_time × focal_length)`
- 用于补充帧到帧的速度，特别是在跟踪最困难的撞击处
- 权重：帧到帧跟踪（主要）+模糊估计（补充，0.2-0.3权重）

#### F4.4：置信度评分
每个速度测量都会根据以下条件获得置信度分数 (0-1)：
- YOLO 的球杆头检测信心
- 跟踪一致性（突然跳跃=低置信度）
- 基于模糊与基于跟踪的协议
- 连续成功跟踪的帧数

向用户显示：速度+置信度指示器（绿色/黄色/红色）

### F5：摆动检测

**优先级：** 高

#### F5.1：状态机```IDLE → PLAYER_DETECTED → READY → SWING_IN_PROGRESS → SWING_COMPLETE → PROCESSING → RESULT → IDLE
```
#### F5.2：检测方法

|过渡 |方法|触发|
|---|---|---|
|空闲→ PLAYER_DETECTED |视觉人体姿态检测|画面中检测到人体 |
| PLAYER_DETECTED → 准备就绪 |静止检测|帧差低于阈值0.5-1秒 |
|准备就绪 → SWING_IN_PROGRESS |动作开始 + 声音嗖嗖 |帧差尖峰和/或音频能量上升|
| SWING_IN_PROGRESS → SWING_COMPLETE | SWING_IN_PROGRESS → SWING_COMPLETE |音频+动作|音频能量衰减+运动速度下降|
| SWING_COMPLETE → 处理中 |自动|立即过渡 |
|处理→结果|管道完成 |分析完毕|
|结果 → 空闲 |超时或用户点击|结果显示3-5秒后自动重置|

#### F5.3：音频触发捕获（第 3 阶段增强）
- 空闲：仅音频监控 (100-300mW)，摄像头以 30fps 预览
- 检测到呼啸 → 切换到 240fps 捕捉
- 冲击瞬态 → 标记冲击帧（±1ms 精度 vs 仅视频的 ±4ms）
- 能量衰减→停止捕获
- 省电：与连续 240fps 相比，节能 10-20 倍

### F6：音频反馈系统

**优先级：** 高 — 对于速度训练期间的免提操作至关重要

#### F6.1：模式
- **蜂鸣模式**（免费套餐）：独特的音调蜂鸣声，通过 AVAudioPlayer 延迟 <50 毫秒
- **语音模式**（高级）：通过 AVSpeechSynthesizer 发出语音警报，约 100-200 毫秒延迟

#### F6.2：事件→声音映射

|活动 |蜂鸣模式 |语音模式 |
|---|---|---|
|检测到玩家 |单低音（200Hz，100ms）| “检测到玩家” |
|准备好（地址已确定）|双升蜂鸣声（400Hz→600Hz）| “准备好了” |
|挥杆捕捉|单亮确认（800Hz，150ms）| “秋千被捕获”|
|速度结果 |三重升序+语音| “[X] 英里每小时”|
|错误：挥杆未命中 |降双音（600Hz→300Hz）| “未检测到摆动，请重试”|
|错误：跟踪丢失 |快速三声蜂鸣声（500Hz×3）| “追踪丢失，请重试” |
|需要调整位置|慢速重复脉冲（400Hz，500ms 间隔）| “调整位置——站在框架中”|
|校准完成 |升起的三音铃声 (C-E-G) | “校准完成” |

#### F6.3：音频路由
- `AVAudioSession` 类别：`.playback`
- 模式：`.voicePrompt`
- 选项：`.duckOthers`、`.interruptSpokenAudioAndMixWithOthers`、`.allowBluetooth`
- 连接时自动路由至 AirPods/蓝牙耳机
- 通过`UINotificationFeedbackGenerator` + `CHHapticEngine`配对的触觉反馈

### F7：滞后角分析（高级）

**优先级：** 高——关键的溢价差异化因素

#### F7.1：测量方法
- 3D身体姿势（`VNDetectHumanBodyPose3DRequest`）提供3D米的肩部、肘部、手腕
- 跟踪管道中的球杆头位置
- 以真实 3D 计算的滞后角：`angle_between(elbow→wrist vector, wrist→club_head vector)`
- 全 240fps 的后捕捉处理 → 释放点检测达到 ±4ms / ±1-2° 精度

#### F7.2：报告的指标|公制|定义 |物超所值|铸造价值|
|---|---|---|---|
| **顶部滞后角** |上杆顶部时的臂轴角度 | 80-100°|相同（设置相似）|
| **臂平行时的滞后角** |下杆时前臂与地面平行时的角度| 80-100°（保持）| 50-70°（提前发布）|
| **滞后保留指数 (LRI)** |比率：手臂平行处的滞后/顶部的滞后| 0.5-0.7 | 0.2-0.4 |
| **发布点** |撞击前手臂旋转的程度，其中滞后开始迅速减少 |撞击前 30-50° |撞击前 90-120° |
| **撞击时杆身倾斜** |冲击时轴与垂直线之间的角度 | +10° 至 +20°（向前）| 0° 或负（翻转）|

#### F7.3：铸造检测逻辑
- **铸造标记**当：LRI < 0.4 或释放点 > 冲击前 90°
- **良好的滞后标记**当：LRI > 0.5 并且释放点在撞击前 < 50°
- **速度损失估计：** `(ideal_LRI - actual_LRI) × calibration_factor × base_speed`

#### F7.4：2D 视差限制
Sportsbox AI 研究表明，2D 正面测量可以显示 31°，而实际 3D 为 72°。我们使用 Apple 的 3D 姿势估计避免了身体关节的这种情况。球杆头位置仍然存在一些深度不确定性，但结合手腕约束（球杆长度半径），3D 角度计算远比纯 2D 准确。

### F8：摇摆重播（高级）

**优先级：** 中

#### F8.1：视频播放
- 慢动作播放捕捉到的挥杆视频
- 播放速度控制（0.25x、0.5x、1x）
- 逐帧擦洗

#### F8.2：叠加
- **手臂/杆身线：** 视频上绘制的前臂（肩→肘→手腕）和杆身（手腕→球杆头）
- **颜色编码：** 绿色（良好的延迟）/黄色（中等）/红色（铸造/早期发布）
- **滞后角度数字：** 在回放时实时显示，更新每一帧
- **速度数字：** 每帧显示球杆头速度
- **释放点标记：** 释放开始处的摆动弧上的视觉指示器
- **冲击标记：** 突出显示冲击框架

### F9：挥杆历史和数据

**优先级：** 中

#### F9.1：数据存储（SwiftData）
- 所有数据都存储在设备本地（v1 中没有云）
- **SwingRecord：** id、时间戳、impactSpeed、confidenceScore、clubType、sessionId、videoURL、isBookmarked
- **SpeedProfile：** 每次挥杆的（frameTimestamp、speedMph、confidence）数组
- **LagMetrics：** lagAngleTop、lagAngleArmParallel、lagRetentionIndex、releasePointDegrees、shaftLeanAtImpact、castingDetected
- **校准数据：**校准方法、每米像素、冲击区域位置、球杆长度、躺角、摆动平面、臂长
- **会话：** id、开始时间、结束时间、swingCount、averageSpeed、maxSpeed、clubType

#### F9.2：历史视图
- 按时段分组的波动列表

## 10. 准确度目标

|版本 |速度精度|滞后角精度|方法|
|---|---|---|---|
| v1.0 | ±5-8 英里/小时 | ±5-10° |基本的帧到帧跟踪、手动校准 |
| v1.1 | ±2-4 英里/小时 | ±3-5° | + 亚像素跟踪、运动模糊分析、卡尔曼平滑、LiDAR 校准 |
| v2.0 | ±1-3 英里/小时 | ±2-3° | + 经过训练的 ML 模型、全传感器融合、可选反射标记 |

**关键关系：**
- 1 像素位置误差 ≈ 0.6 英里/小时速度误差
- 10° 额外保留滞后 ≈ 5 mph 球杆头速度（Chu 等人，2010）
- 一致性（同一挥杆测量之间的低方差）比训练的绝对准确性更重要

**验证方法：**
- 与 Garmin R10（±1 英里/小时俱乐部速度，±3 英里/小时声称）速度进行比较
- 与 HackMotion 比较滞后角（如果有）
- 使用参考设备以不同速度记录 100 多次挥杆
- 报告：平均绝对误差、标准差、相关系数

## 17. 依赖性和风险

|风险|影响 |缓解措施 |
|---|---|---|
| iPhone 240fps 不可靠（实际 162-200fps）|速度计算错误|使用实际的帧时间戳，切勿假设间隔 |
| YOLO 模型不足以应对模糊的球杆杆头 |高速追踪失败 |运动模糊作为信号 + 通过失败进行卡尔曼预测 |
| 2-3m (±2-3cm) 激光雷达精度 |校准误差会导致速度误差|多个校准点，通过底角检查进行自我验证 |
|会话期间的热节流|相机从 240fps 下降 |音频触发的突发捕获，不是连续的。警告用户 |
| ShotVision 显着改善 |竞争威胁|我们的 LiDAR + 3D 姿势 + 音频方法在架构上非常优越 |
| Apple 弃用 VNDetectHumanBodyPose3DRequest | 3D 姿势不可用 |使用相对指标回退到 2D 姿势 |
| App Store 拒绝（相机/麦克风权限）|发射延迟 |清晰的隐私描述，最少的数据收集 |
