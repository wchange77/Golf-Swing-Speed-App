## 1. 2D 到 3D 的速度问题

### 1.1 为什么 2D 跟踪会低估速度

前置摄像头捕捉球杆头在图像平面上的投影。实际的球杆头在倾斜的挥杆平面上沿着 3D 弧线移动。相机只能看到垂直于相机光轴的运动分量——深度分量（朝向/远离相机）是不可见的。

**基本关系：**```v_apparent_2D = v_actual_3D * cos(alpha)
```
其中`alpha`是球杆头的瞬时速度矢量与图像平面之间的角度。在摆动弧中的任何一点，真实速度的一小部分沿着相机的深度轴定向，并且对于 2D 跟踪来说是不可见的。

### 1.2 量化二维速度误差

将高尔夫挥杆视为倾斜平面上的圆周运动。摆动平面与垂直方向（摄像机面向的位置）倾斜`theta` 角度。球杆头在这个倾斜的平面上画出一个圆。

**挥杆弧上的参数位置**（角度 `phi` 从后挥杆顶部测量，通过下挥杆增加）：

对于前置摄像头（摄像头沿 X 轴观察，Y 轴垂直于图像平面，Z 轴水平于图像平面）：```World coordinates of club head on swing arc:
  X(phi) = R * sin(theta) * sin(phi)       // depth: toward/away from camera
  Y(phi) = R * cos(phi)                     // vertical (visible)
  Z(phi) = R * cos(theta) * sin(phi)        // horizontal (visible)
```
其中：
- `R` = 挥杆半径（手臂+球杆长度，通常为1.5-1.8m）
- `theta` = 挥杆平面相对于垂直方向的倾斜（相对于地面的平面角度的补数）
- `phi` = 摆动弧中的角位置

**3D 速度大小：**```v_3D = R * omega
```
其中 `omega` = 角速度 (rad/s)。

**视在 2D 速度（相机看到的）：**```v_2D = R * omega * sqrt(cos^2(phi) + cos^2(theta) * sin^2(phi))
```
**速比（2D/3D）：**```ratio = v_2D / v_3D = sqrt(cos^2(phi) + cos^2(theta) * sin^2(phi))
```
该比率始终 <= 1，这意味着 2D 总是低估真实速度。

### 1.3 摆动相位误差

误差在摆动弧上变化很大：

|挥杆姿势| phi（度）| 2D/3D 比率（驱动器，theta=42）|速度错误|
|---|---|---|---|
|后摆顶部| 0 | 1.00 | 0% |
|早期下跌| 45 | 45 0.87 | 0.87 -13% |
|中下挥杆 | 90 | 90 0.74 | 0.74 -26% |
|后期下跌| 135 | 135 0.87 | 0.87 -13% |
|影响（大约）| 〜160-170 | 0.97-0.99 | -1% 至 -3% |
|低点| 180 | 180 1.00 | 0% |

**关键见解：** 击球时，球杆头位于弧线底部附近（phi 接近 180 度），其中大部分运动发生在可见平面（水平）中。深度分量最小。这意味着**2D 测量在最重要的地方（撞击时）最为准确。**

最差的精度发生在 phi = 90 度（下挥杆期间球杆处于水平位置）时，此时深度分量最大。对于驾驶员挥杆平面（距地面 48 度 = 距垂直面 42 度），此时的简单 2D 测量会低估速度约 26%。

### 1.4 为什么这对我们有利

特别是对于冲击速度测量：
- 击球时，球杆大致水平移动（与地面平行）
- 前置摄像头可以很好地捕捉这种水平运动
- 撞击时的深度误差与`sin^2(theta) * cos^2(phi_impact)`成正比
- 对于 phi_impact 接近 170 度：误差仅为 1-3%

**但是：** 对于全挥杆速度曲线（绘制整个挥杆速度的图表），3D 校正对于避免扭曲的速度曲线至关重要。

## 2. 挥杆平面几何

### 2.1 定义挥杆平面

挥杆平面是球杆头在下挥杆过程中大致轨迹的倾斜圆盘。它可以定义为：

1. **法向向量** `n` = 垂直于平面的单位向量
2. **倾斜角度** `theta_ground` = 飞机与地面之间的角度
3. **中心点** = 脊柱/肩部的大致位置

**来自地址位置校准数据：**```Given:
  - spine_pos: 3D position of spine (base of neck)
  - hand_pos:  3D position of hands at address
  - club_head_pos: 3D position of club head at address

The swing plane contains the spine-to-hand vector and the hand-to-club vector.

plane_normal = normalize(cross(hand_pos - spine_pos, club_head_pos - hand_pos))
```
如果我们只有 2D 数据加上 LiDAR 校准：```Given:
  - lie_angle: angle of club shaft to ground (from manual input or LiDAR)
  - club_length: length of club (from calibration)
  - camera_to_subject_distance: from LiDAR

The swing plane tilt from vertical:
  theta_from_vertical = 90 - lie_angle  (approximate)

For more precision, the swing plane angle differs from the lie angle by a few degrees
because the swing plane is defined by the club head path, not the shaft angle.
TrackMan data shows swing plane is typically 3-5 degrees flatter than shaft plane.
```
### 2.2 典型的摆动平面角度

基于 TrackMan 汇总数据：

|俱乐部|摆动平面（从地面）|从垂直方向倾斜 |典型杆底角 |
|---|---|---|---|
|司机 | 45-50 度 | 40-45 度 | 56-60 度 |
| 3-木| 50-53 度 | 37-40 度 | 58-60 度 |
| 5 号铁杆 | 55-58 度 | 32-35 度 | 60-62 度 |
| 7 号铁杆 | 58-62 度 | 28-32 度 | 62-64 度 |
| 9 号铁杆 | 60-63 度 | 27-30 度 | 64-65 度 |
|密码/软件 | 62-65 度 | 25-28 度 | 64-65 度 |

**男性高尔夫球手的平均得分**（TrackMan）：
- 驾驶员：距地面 48.1 度
- 6 号铁杆：距地面约 59 度

### 2.3 摆动平面法向量

对于前置摄像头，其中：
- X = 深度（朝向相机为正）
- Y = 垂直（向上为正）
- Z = 水平/目标线（对于右手高尔夫球手来说，右侧为正）

右手高尔夫球手的挥杆平面法线大约为：```n = (-sin(theta_from_vertical), 0, cos(theta_from_vertical))
```
这假设该平面包含垂直轴。实际上它会稍微旋转，但这是一个很好的初步近似。

更准确地说，对于与垂直方向倾斜 `alpha` 角度并绕垂直轴旋转 `beta` 的摆动平面：```n_x = -sin(alpha) * cos(beta)
n_y = cos(alpha)                    // small for steep planes
n_z = sin(alpha) * sin(beta)
```
其中 `beta` 说明了摆动平面可能与相机轴不完全对齐的事实。

### 2.4 平面角度如何影响校正因子

摆动弧中任意点的 3D 速度修正系数为：```correction = 1.0 / sqrt(cos^2(phi) + cos^2(theta) * sin^2(phi))
```
其中 `theta` 是相对于垂直方向的倾斜度。

在临界影响区（phi 接近 170 度）：

|平面角度（距地面）| theta（垂直方向）|冲击修正|
|---|---|---|
| 45 度（驾驶员）| 45 度 | 1.01 - 1.03 |
| 55 度（中铁）| 35 度 | 1.005 - 1.02 |
| 63 度（楔形）| 27 度 | 1.003 - 1.01 |

**主要发现：** 冲击时的修正很小 (1-3%)，因为冲击发生在弧底部附近。更陡峭（更直立）的挥杆需要更少的修正。对于中下挥杆期间较平坦的挥杆（发球杆），修正最为显着。

## 3. 透视校正

### 3.1 视角尺度问题

相机使用透视投影：远处的物体显得更小。每米像素比例因子随深度而变化。如果在一个深度（例如球位置）进行校准，但在挥杆过程中球杆头移动到不同的深度，则比例因子是错误的。

**针孔相机型号：**```u = f * X / Z + u0
v = f * Y / Z + v0
```
其中：
- (u, v) = 像素坐标
- (X, Y, Z) = 相机坐标系中的 3D 坐标
- f = 焦距（以像素为单位）
- (u0, v0) = 主点

深度 Z 处的比例因子（每米像素数）为：```pixels_per_metre(Z) = f / Z
```
### 3.2 挥杆过程中的深度变化

对于距高尔夫球手 `D` 距离的前置摄像头，球杆头的深度随着其朝向和远离摄像头摆动而变化：```depth_offset(phi) = R * sin(theta) * sin(phi)
Z(phi) = D + R * sin(theta) * sin(phi)
```
其中：
- D = 摄像机到高尔夫球手的距离（2-3m，在球/站位处测量）
- R = 回转半径 (~1.5-1.8m)
- theta = 挥杆平面与垂直方向的倾斜度
- phi = 摆动弧中的位置

**最大深度偏移：**```max_depth_change = R * sin(theta)
```
对于驱动程序：`1.7m * sin(45 deg) = 1.2m`

这意味着与校准平面相比，球杆头距离相机的距离最多可达 1.2m。

### 3.3 透视比例校正

两帧之间的像素位移测量表观运动。要获得真实的位移，请校正深度：```true_displacement = pixel_displacement * Z_actual / Z_calibration
```
或者等价地：```true_displacement = pixel_displacement / pixels_per_metre_calibration * (Z_actual / Z_calibration)
```
修正系数为：```perspective_correction = Z_actual / Z_calibration = (D + depth_offset) / D
```
### 3.4 视角误差的大小

|相机距离 D |最大深度变化|最大透视误差 |
|---|---|---|
| 2.0米| 1.2 m（驾驶员）| +60% / -37% |
| 2.5 m | 1.2 m（驾驶员）| +48% / -32% |
| 3.0米| 1.2 m（驾驶员）| +40% / -29% |
| 2.0米| 0.8 m（7 号铁杆）| +40% / -29% |
| 3.0米| 0.8 m（7 号铁杆）| +27% / -21% |

**这些是最坏情况下的数字**，在挥杆弧的极限处（上杆顶部、后续挥杆结束）。撞击时，深度偏移很小：```At impact (phi ~ 170 deg):
  depth_offset = R * sin(theta) * sin(170 deg) = R * sin(theta) * 0.17
  For driver: 1.7 * 0.71 * 0.17 = 0.21m
  Perspective error at D=2.5m: 0.21/2.5 = 8.4%
```
**应用校正后，残余误差取决于我们对深度的了解程度。**如果我们将挥杆建模为已知平面上的圆弧，则深度是确定的并且可以精确校正。剩下的错误来自：
- 挥杆平面角度的不确定性（通常为 +/- 3 度）
- 挥杆半径的不确定性（通常为+/- 5cm）
- 偏离完美圆弧（真实的挥杆路径不是完美的圆）

### 3.5 全视角校正公式

给定估计深度 `Z1` 和 `Z2` 处两帧之间的像素位移 `dp`：```real_displacement = dp / ppm_calibration * (Z1 + Z2) / (2 * Z_calibration)
```
其中`ppm_calibration` 是在`Z_calibration` 处测量的每米像素。

对于速度计算：```speed = real_displacement / dt
```
其中 `dt` 是帧之间的实际时间（来自 CMSampleBuffer 时间戳）。

## 4. 速度计算公式

### 4.1 0 级：朴素 2D（当前实现）```pixel_distance = sqrt((x2-x1)^2 + (y2-y1)^2)
real_distance = pixel_distance / pixels_per_metre
speed_ms = real_distance / dt
speed_mph = speed_ms * 2.23694
```
**预期误差：+/- 10-30%，具体取决于摆动相位**
撞击时：+/- 2-8%（因为深度分量很小）

### 4.2 1 级：2D + 透视校正```// Estimate depth at each tracked point using swing plane model
Z1 = D + R * sin(theta) * sin(phi1)
Z2 = D + R * sin(theta) * sin(phi2)

// Correct pixel distance for perspective
corrected_distance = pixel_distance / ppm * (Z1 + Z2) / (2 * D)
speed_ms = corrected_distance / dt
```
从 2D 跟踪位置估计`phi`（角度位置）：```// The vertical component is preserved by front-on camera
// phi can be estimated from the Y coordinate relative to shoulder
cos(phi) = (Y_shoulder - Y_clubhead) / R_apparent
phi = acos(...)
```
**预期改进：撞击时视角误差从 8% 减少至约 2%**

### 4.3 第 2 级：2D 跟踪的全 3D 弧速

给定以像素为单位的 2D 跟踪位置 (u, v) 和已知的挥杆平面，重建弧上的 3D 位置：

**第 1 步：构造一条从相机穿过像素的光线**```ray_direction = normalize((u - u0) / f, (v - v0) / f, 1.0)
```
**步骤 2：使光线与摆动平面相交**

摆动平面通过法线 `n` 的枢轴点（肩部）：```Plane equation: dot(n, P - shoulder) = 0
Ray equation: P = camera_origin + t * ray_direction

t = dot(n, shoulder - camera_origin) / dot(n, ray_direction)
P_3D = camera_origin + t * ray_direction
```
这给出了球杆头在挥杆平面上的 3D 位置。

**步骤 3：计算 3D 速度**```distance_3D = length(P_3D_frame2 - P_3D_frame1)
speed_3D = distance_3D / dt
```
**预期误差：总计 +/- 3-8%（主要由跟踪噪声而非几何形状决定）**

### 4.4 第 3 级：冲击速度提取

冲击速度是最重要的一个数字。从撞击事件周围的帧中提取它：```1. Identify impact frame (audio spike, sudden deceleration, or ball appearance change)
2. Use frames impact-2, impact-1, impact, impact+1, impact+2 (5 frames = 20ms window at 240fps)
3. Calculate speed for each consecutive frame pair
4. Weight by proximity to impact and tracking confidence:

impact_speed = sum(w_i * speed_i) / sum(w_i)

where w_i = confidence_i * gaussian(t_i - t_impact, sigma=0.004)
```
使用更多的帧可以减少噪音；高斯加权（sigma = 4ms，240fps 下大约 1 帧）确保撞击时刻影响最大。

**替代方案：将多项式拟合到冲击附近的速度曲线并在 t_impact 处进行评估**```Fit quadratic: speed(t) = a*t^2 + b*t + c to the 5-7 points around impact
impact_speed = speed(t_impact)
```
这对于单个噪声帧来说更加鲁棒。

### 4.5 运动模糊速度估计

当球杆头快速移动时，会产生运动模糊条纹。条纹长度编码速度信息：```blur_length_metres = streak_length_pixels / pixels_per_metre(Z)
speed_from_blur = blur_length_metres / exposure_time
```
其中 `exposure_time` 来自帧的元数据（CMSampleBuffer 曝光持续时间）。

**在 100 英里/小时 (44.7 m/s) 下，1/1000 秒曝光：**```blur = 44.7 * 0.001 = 0.0447m = 4.47cm
At 2.5m distance with typical phone camera (f ~ 4000 pixels for 1080p):
blur_pixels = 0.0447 * 4000 / 2.5 = 71.5 pixels
```
这是非常可测量的，并提供有用的独立速度估计。

**在 1/2000 秒曝光时（在良好光线下可实现）：**```blur = 44.7 * 0.0005 = 2.24cm = ~36 pixels
```
仍然可测量，但信号较低。

### 4.6 融合速度估计

将帧到帧跟踪速度与运动模糊速度相结合：```// Adaptive weighting based on confidence
alpha = tracking_confidence  // 0.0 to 1.0
beta = blur_confidence       // 0.0 to 1.0

// Normalize weights
w_track = alpha / (alpha + beta)
w_blur = beta / (alpha + beta)

fused_speed = w_track * tracking_speed + w_blur * blur_speed
```
**模糊置信度**在以下情况下应该很高：
- 模糊条纹具有明显的方向性（不仅仅是噪音）
- 条纹长度与跟踪速度一致（30%以内）
- 准确知道曝光时间

在以下情况下，**跟踪置信度**应该很高：
- YOLO检测置信度高
- 卡尔曼滤波器创新（预测误差）小
- 存在连续跟踪帧（平滑轨迹）

### 4.7 置信度评分```confidence = base_tracking_confidence
           * trajectory_smoothness_factor
           * blur_agreement_factor
           * constraint_satisfaction_factor

where:
  base_tracking_confidence: from YOLO/Vision detection (0-1)

  trajectory_smoothness_factor: 1.0 if the tracked positions follow a smooth arc,
    drops toward 0.5 for erratic jumps. Computed as:
    1.0 - clamp(jerk / max_expected_jerk, 0, 0.5)

  blur_agreement_factor: 1.0 if tracking and blur speeds agree within 10%,
    0.8 if within 20%, drops linearly to 0.5 at 50% disagreement.
    = 1.0 - 0.5 * clamp(|speed_track - speed_blur| / speed_track / 0.5, 0, 1)

  constraint_satisfaction_factor: 1.0 if club head is within club_length of wrist,
    drops as the constraint is violated.
    = 1.0 - clamp((distance_to_wrist - club_length) / club_length, 0, 0.5)
```

## 5. 准确度分析

### 5.1 错误预算

|错误来源|震级（撞击时）|缓解措施 |
|---|---|---|
| 2D 深度投影 | 1-3% |摆动平面校正|
|透视尺度| 2-8% |深度校正比例因子 |
|像素跟踪噪声 | +/- 1-3 像素 = 3-9% |卡尔曼滤波器，多帧平均 |
|帧定时抖动| 0.1-0.5% |使用实际时间戳 |
|校准秤误差| 2-5% |激光雷达校准 |
|摆动平面角度不确定度| 1-3% |地址位置校准|
|非圆弧| 0.5-1% |小——近击球时挥杆弧度近圆形|

### 5.2 像素误差加速误差转换

在 240 fps 下，时速 100 英里的球杆头大约移动：```100 mph = 44.7 m/s
Distance per frame = 44.7 / 240 = 0.186m = 18.6cm
At 2.5m camera distance, with iPhone 13 Pro (f ~ 26mm, sensor 5.7mm wide):
  pixels_per_metre at 2.5m = (1920 / sensor_width_m) * (f / D)
  For iPhone 13 Pro main camera: approximately 770 pixels/metre at 2.5m distance
  18.6cm = 143 pixels per frame
```
**1 个像素位置误差 = 2 个位移像素误差（最坏情况）= 2/143 = 1.4% 速度误差**

更准确地说：```speed_error_mph = (pixel_error / pixels_per_frame_displacement) * actual_speed

For 1-pixel error at 100mph:
  speed_error = (1/143) * 100 = 0.7 mph per pixel of position error
  With 2 positions (start/end): ~1.4 mph per pixel of position error
```
不同速度下：
|速度（英里/小时）| 240fps 时的像素/帧 | 1 像素误差（英里/小时）|
|---|---|---|
| 50 | 50 72 | 72 0.7 | 0.7
| 80| 115 | 115 0.7 | 0.7
| 100 | 100 143 | 143 0.7 | 0.7
| 120 | 120 172 | 172 0.7 | 0.7

以英里/小时为单位的误差大约恒定为每像素位置误差 0.7 英里/小时（相机距离为 2.5 m，宽度为 1920 像素）。这是因为位移和速度都是线性缩放的。

### 5.3 帧速率对准确性的影响```displacement_per_frame = speed / fps
pixel_displacement = displacement_per_frame * pixels_per_metre

Higher fps = smaller displacement per frame = pixel errors are a larger fraction
```
矛盾的是，较高的帧速率会降低每帧的精度。但多帧平均可以恢复这一点：

|帧率 |像素/帧（100 英里/小时）| 1 像素错误 |使用 3 帧平均 |
|---|---|---|---|
| 120 | 120 287 | 287 0.35% | 0.20% |
| 240 | 240 143 | 143 0.70% | 0.40% |

## 6. 关键公式总结

### 6.1 根据校准数据确定摆动平面法线```// Given lie angle and camera-to-subject setup
let theta = (90.0 - lieAngleDegrees) * .pi / 180.0  // tilt from vertical in radians
let planeNormal = SIMD3<Float>(
    -sin(Float(theta)),  // X: depth component
    0,                   // Y: vertical (plane contains vertical axis, approximately)
    cos(Float(theta))    // Z: horizontal component
)
```
### 6.2 挥杆弧上任意点的深度```// phi: angular position on swing arc (0 = top, pi = bottom/impact)
// R: swing radius in metres
// theta: swing plane tilt from vertical
// D: camera-to-golfer distance in metres
func depthAtArcPosition(phi: Double, R: Double, theta: Double, D: Double) -> Double {
    return D + R * sin(theta) * sin(phi)
}
```
### 6.3 透视校正速度```func correctedSpeed(
    pixelDisplacement: Double,
    ppmAtCalibrationDepth: Double,
    calibrationDepth: Double,
    depth1: Double,
    depth2: Double,
    dt: Double
) -> Double {
    let avgDepth = (depth1 + depth2) / 2.0
    let correctedDisplacementMetres = (pixelDisplacement / ppmAtCalibrationDepth) * (avgDepth / calibrationDepth)
    return correctedDisplacementMetres / dt
}
```
### 6.4 2D 像素 + 摆动平面交点的 3D 位置```func reconstruct3DPosition(
    pixelU: Double, pixelV: Double,
    focalLengthPixels: Double,
    principalPoint: (Double, Double),
    cameraPosition: SIMD3<Float>,
    planeNormal: SIMD3<Float>,
    planePoint: SIMD3<Float>  // shoulder/pivot position
) -> SIMD3<Float>? {
    // Ray from camera through pixel
    let rayDir = normalize(SIMD3<Float>(
        Float((pixelU - principalPoint.0) / focalLengthPixels),
        Float((pixelV - principalPoint.1) / focalLengthPixels),
        1.0
    ))

    // Intersect ray with swing plane
    let denom = dot(planeNormal, rayDir)
    guard abs(denom) > 1e-6 else { return nil }  // ray parallel to plane

    let t = dot(planeNormal, planePoint - cameraPosition) / denom
    guard t > 0 else { return nil }  // intersection behind camera

    return cameraPosition + t * rayDir
}
```
### 6.5 2D 跟踪的角位置估计```func estimateArcAngle(
    clubHeadY: Double,     // vertical pixel position of club head
    shoulderY: Double,     // vertical pixel position of shoulder/pivot
    swingRadiusPixels: Double
) -> Double {
    // cos(phi) = (shoulderY - clubHeadY) / R_pixels
    // Note: pixel Y increases downward, so club below shoulder = positive cos(phi)
    let cosPhiRaw = (shoulderY - clubHeadY) / swingRadiusPixels
    let cosPhi = max(-1.0, min(1.0, cosPhiRaw))
    return acos(cosPhi)
}
```
### 6.6 运动模糊速度```func speedFromBlur(
    streakLengthPixels: Double,
    exposureTimeSeconds: Double,
    pixelsPerMetre: Double,
    depthCorrectionFactor: Double  // Z_actual / Z_calibration
) -> Double {
    let streakMetres = (streakLengthPixels / pixelsPerMetre) * depthCorrectionFactor
    return streakMetres / exposureTimeSeconds  // m/s
}
```
### 6.7 融合冲击速度```func fusedImpactSpeed(
    trackingSpeeds: [(speed: Double, confidence: Double, timestamp: Double)],
    blurSpeeds: [(speed: Double, confidence: Double, timestamp: Double)],
    impactTimestamp: Double,
    sigma: Double = 0.004  // 4ms Gaussian width
) -> (speed: Double, confidence: Double) {
    var weightedSum = 0.0
    var totalWeight = 0.0

    for s in trackingSpeeds {
        let timeWeight = exp(-pow(s.timestamp - impactTimestamp, 2) / (2 * sigma * sigma))
        let w = s.confidence * timeWeight
        weightedSum += w * s.speed
        totalWeight += w
    }

    for s in blurSpeeds {
        let timeWeight = exp(-pow(s.timestamp - impactTimestamp, 2) / (2 * sigma * sigma))
        let w = s.confidence * timeWeight * 0.5  // blur gets lower base weight
        weightedSum += w * s.speed
        totalWeight += w
    }

    guard totalWeight > 0 else { return (0, 0) }
    return (weightedSum / totalWeight, min(1.0, totalWeight / 3.0))
}
```

## 7. 推荐实施

### 7.1 第 1 阶段 (v1.0)：基本 2D + 透视校正

1. 保留现有的`SpeedCalculator.instantaneousSpeed()`作为后备
2.添加挥杆平面角度作为校准参数（球杆类型默认）
3.使用摆动弧模型添加每帧深度估计
4. 对像素位移应用透视校正
5. 使用多项式拟合提取冲击速度

**预期精度改进：从 +/- 10-15 英里每小时到 +/- 5-8 英里每小时**

### 7.2 第 2 阶段 (v1.1)：3D 重建

1. 实现光线平面相交以进行全 3D 位置重建
2. 使用 Apple 的 3D 身体姿势作为肩部/手腕位置作为枢轴点
3. 计算连续位置之间的 3D 距离
4. 添加运动模糊速度估计作为补充信号
5. 实施置信加权融合

**预期精度改进：从 +/- 5-8 英里/小时到 +/- 3-5 英里/小时**

### 7.3 第 3 阶段 (v2.0)：LiDAR + ML

1. 使用激光雷达进行精确的挥杆平面和刻度校准
2. 根据累积数据训练 ML 模型以预测校正因子
3.添加亚像素跟踪细化
4. 针对模糊估计进行交叉验证以保证质量

**预期精度改进：从 +/- 3-5 英里每小时到 +/- 2-4 英里每小时**

### 7.4 实施优先级

以最少的实施工作实现最大影响的变更：

1. **每种球杆类型的挥杆平面角度**（1小时）--添加查找表，应用校正因子
2. **透视深度校正**（2小时）——从弧线位置估计深度，校正比例
3. **冲击速度多项式拟合**（1小时）——通过在冲击附近拟合曲线来降低噪音
4. **运动模糊速度估计**（3小时）——需要模糊条纹检测算法
5. **光线平面 3D 重建**（4 小时）——需要相机内在函数 + 平面估计
6. **置信加权融合**（2小时）——将所有信号与质量权重结合起来
