## 1. 重要参考：SwingVision（网球）

> **这是与我们的项目最相关的竞争对手/参考。** SwingVision 证明智能手机仅使用摄像头进行速度跟踪在商业上是可行的。

### 概述

|领域 |详情 |
|--------|---------|
| **全名** | SwingVision：网球和匹克球的人工智能统计 |
| **公司** | SwingVision Inc.（由 Swupnil Sahai 和 Richard Hsu 创立）|
| **类别** |人工智能支持的体育分析（网球/匹克球）|
| **价格** |免费套餐 + 高级订阅（约 14.99 美元/月或 99.99 美元/年）|
| **平台** | iOS（iPhone、iPad）、Apple Watch |
| **所需硬件** | iPhone 或 iPad 安装在栅栏/三脚架上；无需外部传感器|

### 创始团队及背景

- **Swupnil Sahai（首席执行官）：** Tesla Autopilot 前高级计算机视觉工程师。直接与埃隆·马斯克 (Elon Musk) 合作研究自动驾驶的 3D 对象跟踪。加州大学伯克利分校毕业生（经济学、应用数学、统计学）。两届 WWDC 学者。
- **Richard Hsu（联合创始人）：** Sahai 在加州大学伯克利分校的大学室友。
- **团队背景：** 来自特斯拉和苹果的人工智能专家。由澳大利亚网球协会、索尼和 Techstars 提供风险投资支持。
- **关键见解：** Sahai 意识到用于自动驾驶汽车的相同 3D 对象跟踪技术可以跟踪网球场上的球。

### 技术深入探讨

|方面|详情 |
|--------|---------|
| **核心技术** |通过 CoreML 使用 Apple 神经引擎的设备上计算机视觉 + 机器学习 |
| **相机要求** |标准 iPhone/iPad 后置摄像头最低 60 fps |
| **处理** |完全在设备上——实时分析无需互联网连接 |
| **神经引擎依赖性** |应用程序“如果没有神经引擎基本上是不可能的”（直接引用苹果开发者的故事）|
| **视频处理** |每秒实时处理约 200 万像素 60 次 |
| **机器学习模型** |专有模型经过数千小时的网球镜头训练；优化为“尽可能精简”|
| **球追踪** |跟踪整个飞行路径上的球轨迹 |
| **玩家追踪** |跟踪球员的移动和定位|

### 速度测量方法- **工作原理：** 通过视频帧整个飞行路径上的平均速度来计算球速。
- **与雷达的主要区别：** 读数比电视雷达低约 20%，因为雷达测量撞击时的峰值速度，而 SwingVision 计算整个轨迹的平均速度。
- **对高尔夫的影响：** 高尔夫的类似方法需要考虑到这一点 - 要么测量平均速度并清晰地传达，要么开发基于轨迹的外推法来估计撞击速度。

### 准确性和验证

|公制|准确度|
|--------|----------|
| **球速** |雷达参考值的约 10% 以内 |
| **球的放置** |准确度在 ~5% 之内 |
| **速度 ICC** | 0.76--0.80（有效性良好，经过同行评审）|
| **安置 ICC** | 0.83--0.87（良好到非常好的有效性）|
| **科学来源** | MDPI 应用科学 13(10):6195，同行评审研究 |

### 已知限制

- 小球尺寸和高速挑战的球跟踪
- 弹跳区域受遮挡影响（玩家遮挡视线）
- 最低要求 60 fps - 较低的速率会完全错过球的弹跳
- 精度因相机设置质量和定位而异
- 速度精度随着角度不理想而降低

### 为什么这对我们的项目很重要

1. **证明仅使用摄像头的速度测量可以在没有外部硬件的标准 iPhone 上工作**
2. **证明设备上的 ML** 足够快，可以以 60 fps 进行实时对象跟踪
3. **CoreML + 神经引擎** 是此类应用程序经过验证的技术堆栈
4. **10% 的速度精度**是仅使用相机方法的现实基线期望
5. **网球的移动速度为 50-160 英里/小时** -- 高尔夫球杆头的移动速度为 60-130 英里/小时，这是一个相当的速度范围
6. **但是：** 在很长的飞行路径（许多帧）中都可以看到网球；击球时的高尔夫球杆头仅在几帧中可见，这使得跟踪挑战变得不同并且可以说更加困难

## 2. 仅摄像头的高尔夫速度测量应用程序

### 2a。 ShotVision（启动监视器应用程序）

> **最接近我们高尔夫概念的现有竞争对手。** 仅使用 iPhone 摄像头作为启动监视器。

|领域 |详情 |
|--------|---------|
| **全名** | ShotVision 发射监视器 |
| **公司** |射击视觉 |
| **类别** |基于摄像头的高尔夫发射监视器|
| **价格** |免费（有限）/专业版：~9.99 美元/月或 69.99 美元/年 |
| **平台** |仅限 iOS |
| **所需硬件** |仅iPhone后置摄像头——无外部传感器|

#### 技术

- 通过 iPhone 的后置摄像头使用**计算机视觉**来检测和跟踪高尔夫球和球杆
- **直接测量：** 球速、水平和垂直发射角度、球杆路径
- **算法计算：** 球杆面角度、旋转、旋转轴、飞行距离、总距离
- 需要使用对齐工具将手机放置在与击球方向平行的位置

#### 准确性评估- **良好的条件：**“总体上相当准确，并且足够准确，足以清楚地了解您的挥杆”（MyGolfSpy）
- **恶劣条件：** 在光线不好的情况下，与 Foresight GC Quad 相比，指标可能会降低 30-50%
- **设备依赖性：** 准确度直接随 iPhone 型号变化 - 较新的手机更准确
- **检测可靠性：** 并非所有镜头都能记录；一些击球良好的球未能被检测到
- **关键因素：** 灯光是性能的“成败”

#### 已知限制

- 对光照条件高度敏感
- 较旧的 iPhone 产生的结果准确度明显较低
- 相机定位必须精确（与拍摄线平行）
- 射击检测并非 100% 可靠
- 在明亮的阳光或弱光条件下的户外使用存在问题

## 3. 智能手机摄像头高尔夫挥杆分析应用程序

这些应用程序使用手机摄像头进行**视觉分析**，但不会尝试仅通过摄像头测量速度。

|领域 |详情 |
|--------|---------|

| **平台** | iOS、安卓 |
| **所需硬件** | iPhone/iPad 摄像头（240fps 模式的后置摄像头）|

#### 技术

- **正在申请专利的人工智能挥杆检测：** 自动检测并记录挥杆，免提
- 在支持的 iPhone 上以高达 **240 fps** 的速度录制（仅限后置摄像头）

- 自动绘制参考线（球杆线、颈部到球线）
- **不测量速度** -- 纯粹的视觉/位置分析

#### 创新方法

- 免提、自动录制和修剪是一项强大的用户体验创新
- 基于人工智能的摆动检测消除了手动视频剪辑

## 9. 我们项目的要点

### 机会差距

1. **没有任何高尔夫应用程序能够成功地仅通过手机摄像头高精度测量杆头速度。** ShotVision 尝试了这一点，但在非理想条件下的可靠性和准确性方面遇到了困难。

2. **SwingVision 证明核心概念在网球领域有效**——使用 CoreML 和神经引擎从 iPhone 进行仅摄像头的速度测量，相对于雷达的准确度约为 10%。

3. **要超越的准确度栏约为 12%**（Zepp Golf 基于 IMU 的随机误差）。如果我们仅使用手机摄像头就能将雷达测量的杆头速度控制在 10% 以内，那么我们就能与专用可穿戴传感器竞争。

### 竞争对手的技术教训|课程 |来源 |寓意 |
|--------|--------|-------------|
| CoreML + 神经引擎必不可少 |摇摆视觉|基于 Apple 的设备上 ML 堆栈构建 |
|至少 60 fps，用于跟踪快速物体 |摇摆视觉| iPhone 240 fps 慢动作模式可能是一个主要优势
|平均速度！=峰值速度| SwingVision（与雷达差距 20%）|需要校准模型将观察到的运动转换为冲击速度 |
|照明很关键| ShotVision（准确度损失 30-50%）|必须处理可变照明或需要受控条件 |
|相机定位非常重要|射击视觉 |需要强大的设置指导和对齐工具|
|射击检测的可靠性很难| ShotVision（未投篮）|大力投资检测可靠性|
|后处理可以补充实时性| V1 Golf（球追踪）|可进行实时预估+精细化后处理计算 |
| 2D 视频的 3D 姿势已经成熟 | Sportsbox AI（30+分）|可以添加身体/挥杆分析作为补充功能 |

### 关键技术差异：网球与高尔夫球杆

|因素 |网球 (SwingVision) |高尔夫球杆头（我们的应用程序）|
|--------|--------------------------------------|------------------------|
| **物体大小** |直径约 6.7 厘米 | ~10 厘米脸宽，薄型 |
| **速度范围** | 50-160 英里/小时（球）| 60-130 英里/小时（杆头）|
| **框架可见** |许多（穿过球场的完整飞行路径）|很少（仅在撞击区附近）|
| **背景** |球场面积（可预测）|草/垫（可变）|
| **闭塞** |偶尔（玩家身体） |频繁（手、手臂、身体）|
| **测量区域** |完整轨迹 |需要捕捉撞击附近的小弧线 |
| **色彩对比** |绿/蓝球场上的黄球 |可变背景上的黑暗俱乐部|

### 推荐的技术方法（通过研究得出）

1. **使用 240 fps 慢动作模式** - 这比 SwingVision 的 60 fps 要求多出 4 倍的帧数，这一点至关重要，因为我们可见的球杆帧数较少
2. **目标 CoreML + 神经引擎** 用于设备上处理（由 SwingVision 证明）
3. **建立校准模型**，将观察到的球杆到球杆的运动转换为估计的击球速度
4. **处理 SwingVision 20% 差距所确定的“平均与峰值”问题**
5. **投资强大的照明检测**——ShotVision 的最大弱点
6. **考虑仅跟踪球杆**（如 OptiShot）——测量球杆并估计球数据可能比同时跟踪两者更可行
7. **目标是 <10% 的准确度**，以击败基于 IMU 的传感器（Zepp 的 12%）
8. **提供清晰准确的通信**——尽管准确度低于雷达，但 SwingVision 通过透明的方法取得了成功
