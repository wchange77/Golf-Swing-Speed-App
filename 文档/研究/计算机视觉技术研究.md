#### 论文：GolfDB：高尔夫挥杆序列视频数据库
- **作者：** William McNally、Kanav Vats 等人。
- **年份：** 2019
- **出版物：** IEEE CVPR 研讨会 (CVSports)
- **主要贡献：** 第一个专门用于高尔夫中 CV 应用的实质性基准数据库（1400 个高尔夫挥杆视频，390k+ 帧）。推出了 SwingNet，一个轻量级深度神经网络基线。

- **相关性：** 建立规范的摆动阶段分割框架。对于自动化摆动检测和相位识别至关重要。
- **链接：** [arXiv：1903.06528](https://arxiv.org/abs/1903.06528)

## 2. 计算机视觉技术深入研究

### 2.1 光流

光流通过分析像素强度变化来估计连续帧之间对象的表观运动。对于时速超过 100 英里的高尔夫球杆头跟踪，这是测量位移的主要技术。#### 2.1.1 Lucas-Kanade（稀疏光流）
- **类型：**稀疏（仅跟踪选定的特征点）
- **工作原理：** 假设每个跟踪点周围的小窗口（~15x15 像素）内流量恒定。使用空间强度梯度的最小二乘法求解光流方程。使用迭代细化和图像金字塔（通常为 3 级）来处理较大的位移。
- **高尔夫的优势：** 计算量轻（在移动设备上具有实时能力）。如果可以可靠地检测到，则适合跟踪特定点，例如球杆头尖端。金字塔方法可处理中等位移。
- **高尔夫的限制：** 假设帧间小运动 - 在 30fps 下，100mph 的球杆头每帧移动约 60+ 像素，这超出了小运动假设。需要良好的特征点来跟踪，并且球杆头可能没有足够的纹理。运动模糊失败。
- **OpenCV 函数：** `cv2.calcOpticalFlowPyrLK()`
- **该项目的结论：** 边缘。需要更高的帧速率（120+ fps）或帧插值才能将位移纳入范围内。可用于跟踪移动较慢的身体标志（手腕、肩膀）。

#### 2.1.2 Farneback（密集光流）
- **类型：** 密集（计算每个像素的流量）
- **工作原理：** 使用多项式展开（二次函数）近似每个像素的邻域。通过分析这些多项式表示在帧之间如何变化来估计位移场。
- **高尔夫的优势：** 提供整个框架的运动场，有助于识别高运动区域（球杆）。无需显式特征检测。适合检测俱乐部移动最快的位置。
- **高尔夫的限制：** 计算成本高昂（在移动设备上不是实时全分辨率）。与 Lucas-Kanade 相同的大排量问题。对运动模糊敏感。
- **OpenCV 函数：** `cv2.calcOpticalFlowFarneback()`
- **此项目的结论：** 对于摆动相位检测（识别快速运动何时开始/结束）有用，而不是精确的速度测量。可以通过最大流量大小来识别俱乐部区域。#### 2.1.3 RAFT（深度学习密集光流）
- **类型：** 密集、基于深度学习
- **工作原理：** 三阶段架构：(1) 特征编码器从两个帧中提取每像素特征，(2) 相关体积为所有像素对构建多尺度 4D 相关体积，(3) 循环更新使用 GRU 单元和相关查找迭代地细化流量估计。
- **高尔夫的优势：** 处理大位移的能力远远优于经典方法（基准测试准确度提高 30%）。亚像素精度。跨领域的强泛化性。
- **高尔夫的限制：** 需要 GPU 进行实时推理。预先训练的模型可能无法完美地推广到运动模糊的球杆头。每帧对的处理时间约为 100 毫秒。
- **结果：** KITTI 上的 F1-all 误差为 5.10%，Sintel 上的 EPE 为 2.855 像素。
- **此项目的结论：** 如果 GPU 推理可用，则为最佳精度选项。可以在捕获的视频上离线运行。大运动能力使其成为最适合 100 英里/小时以上球杆杆头跟踪的光流方法。

### 2.2 背景扣除

背景减除将移动的前景对象与静态（或缓慢变化）的背景分开。对于高尔夫来说，这将高尔夫球手和球杆与练习场/球场隔离。

#### 2.2.1 MOG2（高斯混合 2）
- **工作原理：** 将每个像素的背景建模为 K 个高斯分布的混合。随着时间的推移更新模型。在背景模型下当前值具有低概率的像素被分类为前景。
- **参数：** `history`（影响模型的帧数）、`varThreshold`（背景分类阈值）、`detectShadows`（阴影检测能力）。
- **高尔夫的优势：** 快速（适合实时处理）。适应逐渐的光照变化。可用阴影检测。适合将移动的高尔夫球手/球杆与静态背景隔离。
- **高尔夫的限制：** 需要多个帧来构建稳定的背景模型。相机移动时性能会下降。 “历史”参数需要调整——较小的值用于快速移动，较大的值用于检测细微的运动。不区分不同的移动物体。
- **OpenCV：** `cv2.createBackgroundSubtractorMOG2()`
- **这个项目的结论：** 适合“有运动吗？”问题（摆动起始检测）。当相机静止时（安装在三脚架上的手机），可有效隔离球杆挥杆区域。不适合精确的球杆头定位。#### 2.2.2 KNN（K 最近邻）
- **工作原理：** 非参数方法，根据样本历史记录中的 k 个最近邻对每个像素进行分类。
- **高尔夫的优势：** 在快速变化的背景下效果更好（例如，树木被吹，其他高尔夫球手）。测试中与人类分割的相似度更高。
- **高尔夫的限制：** 比 MOG2 慢。与上述相同的一般限制。
- **OpenCV：** `cv2.createBackgroundSubtractorKNN()`
- **该项目的结论：** 当背景是动态的（室外有风、人们行走）时，优于 MOG2。否则，就速度而言，MOG2 是首选。

### 2.3 模板匹配

模板匹配通过在图像上滑动模板并计算每个位置的相似度分数来搜索较大图像中的小模板图像（感兴趣的对象）。

- **工作原理：** 给定球杆头的模板补丁，将其滑过每个帧并计算归一化互相关 (NCC) 或平方差和 (SSD)。相似度图中的峰值表示球杆头位置。
- **OpenCV 函数：** `cv2.matchTemplate()` 以及 `cv2.TM_CCOEFF_NORMED` 等方法
- **高尔夫的优势：** 易于实施。如果球杆头外观一致且独特，则效果很好。
- **高尔夫的限制：** 对比例变化极其敏感（球杆头在距离相机更近/更远时显得更大/更小）。无法处理旋转（球杆在挥杆过程中大幅旋转）。由于运动模糊而完全失败（模板变得无法识别）。对光照变化不稳健。对于大的搜索区域来说速度很慢。
- **增强：** 可以与金字塔Lucas-Kanade结合：使用模板匹配进行初始检测，然后使用pyrLK进行跟踪。
- **该项目的结论：** 很大程度上不适合作为快速移动的球杆头的主要跟踪方法。当球杆静止且轮廓清晰时，可用于在瞄准位置（挥杆开始之前）进行初始球杆头检测。

### 2.4 轮廓检测与跟踪

轮廓检测通过查找沿着边缘的曲线来识别图像中对象的边界。- **管道：** (1) 转换为灰度，(2) 应用高斯模糊，(3) 边缘检测 (Canny) 或二进制阈值，(4) `cv2.findContours()`，(5) 按区域/形状过滤，(6) 跨帧跟踪。
- **Canny 边缘检测：** 使用梯度幅度和非极大值抑制以及滞后阈值来查找边缘像素。适合寻找球杆杆身轮廓。
- **高尔夫的优势：** 使用背景减法输出（查找前景斑点的轮廓）。可以将球杆头位置估计为检测到的球杆杆身轮廓的端点。形态学操作（膨胀、腐蚀）可以清除噪声检测。
- **高尔夫的限制：** 高速行驶的球杆头会产生严重的运动模糊，导致边缘检测不可靠。当对象重叠时轮廓会合并。对于快速、不稳定的运动来说，跨帧匹配轮廓是不可靠的。细的球杆杆身可能无法产生坚固的轮廓。
- **该项目的结论：** 作为辅助技术很有用。背景扣除隔离挥杆区域后，轮廓分析可以帮助估计球杆方向和终点。作为冲击速度下的主要跟踪方法并不可靠。

### 2.5 斑点检测

斑点检测可查找图像中与周围区域相比亮度或颜色不同的区域。

- **OpenCV SimpleBlobDetector：** (1) 对图像进行多个级别的阈值（minThreshold 到 maxThreshold，按 ThresholdStep 步进），(2) 在每个二值图像中查找连接的白色像素组，(3) 计算中心并合并比 minDistBetweenBlobs 更近的斑点，(4) 按面积、圆度、凸度、惯性、颜色进行过滤。
- **高尔夫的优势：** 如果球杆头具有独特的颜色或反光标记，斑点检测可以有效地定位它。通过过滤器参数进行简单配置。
- **高尔夫的限制：** 要求球杆头形成明显的斑点（高速运动模糊很困难）。球杆头很小，可能不符合最小面积阈值。背景混乱会产生误报。对于单 blob 场景，`findContours` 更快。
- **此项目的结论：** 如果将彩色标记/贴纸放置在球杆头上，则可以工作。如果没有标记，自然的球杆头外观不可能在高速下形成可靠的斑点。更适合检测静止的球或颜色鲜艳的球杆握把。

### 2.6 用于运动预测的卡尔曼滤波

卡尔曼滤波器是一种递归状态估计器，它预测系统的下一个状态（位置、速度），然后使用新的测量来校正预测。- **两步过程：**
  1. **预测：** 使用运动模型（恒定速度或恒定加速度）从先前状态估计当前状态（位置、速度、加速度）。
  2. **更新：** 将预测与新测量（检测到的位置）相结合，通过不确定性（协方差）对每个测量进行加权。
- **球杆头的状态向量：** `[x, y, vx, vy, ax, ay]`（像素空间中的位置、速度、加速度）
- **高尔夫的优势：**
  - 处理错过的检测：如果在帧中未检测到球杆头（运动模糊、遮挡），卡尔曼滤波器将提供预测位置。
  - 平滑噪声检测：平均消除逐帧位置估计中的抖动。
  - 预测未来位置：缩小下一帧检测的搜索区域（动态 ROI）。
  - 计算量很小：以微秒为单位运行。
- **高尔夫的限制：**
  - 假设线性运动模型（恒定速度或加速度）。高尔夫挥杆是高度非线性的（下挥杆期间加速度发生巨大变化）。
  - 非线性动力学所需的扩展卡尔曼滤波器 (EKF) 或无迹卡尔曼滤波器 (UKF)。
  - 需要一种检测方法来提供测量结果；不检测物体本身。
- **该项目的结论：** 任何检测方法的必备伴侣。应与选择的任何检测器（YOLO、blob、轮廓）配对，以处理丢帧并提供平滑的轨迹估计。 CNN 检测 + 卡尔曼预测的组合已被证明对高尔夫球跟踪有效 (arXiv:2012.09393)，并且同样适用于球杆头跟踪。

### 2.7 深度学习目标检测（YOLO、SSD）

#### 2.7.1 YOLO（你只看一次）
- **工作原理：** 单通道检测。将图像划分为网格，同时预测每个单元格的边界框和类概率。当前版本（YOLOv8、YOLOv11）使用 CSPDarknet 主干、PANet 颈部和解耦头部。
- **速度：** GPU 上 155+ FPS。 YOLOv8-nano 可以在移动设备上以 30+ FPS 的速度运行。
- **高尔夫的优势：**
  - 可以训练以检测“高尔夫球杆头”作为自定义类别。
  - 实时推理可实现实时跟踪。
  - 边界框输出给出速度计算的位置。
  - 从 COCO 数据集（存在“运动球”类）进行迁移学习可加速训练。
- **高尔夫的限制：**
  - 球杆头在画面中非常小（约 10-30 像素）。
  - 高速运动模糊使球杆头看起来像一条条纹，而不是一个明显的物体。
  - 需要标记的训练数据（跨多个帧的球杆头上的边界框）。
  - 对于非常小的物体，检测精度急剧下降。
  - 可能需要平铺或裁剪和检测策略。
- **推荐方法：** 在以预期挥杆弧为中心的裁剪 ROI 块上训练 YOLOv8-small。使用卡尔曼滤波器预测下一帧的 ROI。#### 2.7.2 SSD（单次多盒检测器）
- **工作原理：** 与 YOLO 类似的单通道方法，但使用来自主干 CNN 不同层的多尺度特征图来检测各种尺寸的对象。
- **优点：** 擅长检测多个尺度的物体。比两级探测器更快。
- **限制：** 对于小物体来说，通常不如现代 YOLO 变体准确。与 YOLO 生态系统相比，社区支持/工具更少。
- **结论：** 对于此应用程序，YOLO 比 SSD 更受青睐，因为最新版本中的小物体检测效果更好，而且工具（Ultralytics）更出色。

### 2.8 点跟踪（TAPIR、CoTracker）

现代学习点跟踪器跟踪视频帧中的任意像素，处理遮挡和外观变化。

#### 2.8.1 TAPIR（通过每帧初始化和时间细化跟踪任意点）
- **开发者：** Google DeepMind
- **工作原理：** 从 TAP-Net 初始化轨迹，然后使用受 PIP 启发的架构进行细化。每帧初始化可实现鲁棒性。
- **性能：** 与之前的方法相比，DAVIS 基准上的平均 Jaccard 绝对提高了约 20%。在 256x256 视频上以 40 FPS 跟踪 256 个点。
- **高尔夫的优势：** 可以在整个挥杆过程中跟踪球杆头上用户指定的点。处理遮挡（球杆位于身体后面）。不需要特定于高尔夫的训练数据。
- **限制：** 需要 GPU。在极端运动模糊期间可能会丢失点。 256x256 分辨率对于精确测量来说较低。
- **链接：** [貘](https://deepmind-tapir.github.io/) | [GitHub](https://github.com/google-deepmind/tapnet)

#### 2.8.2 CoTracker / CoTracker3
- **开发者：** Meta AI (FAIR)
- **工作原理：** 基于 Transformer 的模型，联合（而不是独立）跟踪密集点，并考虑它们的相关性。 CoTracker3 (2024) 使用伪标签，训练数据减少了 1000 倍。
- **高尔夫的优势：** 多点（球杆头、杆身、手）的联合跟踪提高了鲁棒性。可以跟踪被遮挡的点和摄像机视图之外的点。最先进的准确性。
- **发布：** ECCV 2024
- **链接：** [协同追踪器](https://co-tracker.github.io/) | [GitHub](https://github.com/facebookresearch/co-tracker)

#### 该项目的结论：
点跟踪器是通过手机视频测量球杆头速度的**最有前途的方法**。工作流程将是：
1. 用户在第一帧标记球杆头（或自动检测瞄准位置）
2. TAPIR/CoTracker 在整个挥杆过程中跟踪该点
3. 帧之间的像素位移给出速度数据
4.卡尔曼滤波器平滑轨迹

关键问题是这些跟踪器是否能够跟踪撞击时的极端运动模糊。需要使用真实的高尔夫挥杆视频进行测试。

### 2.9 帧插值（FILM、RIFE）

帧插值在现有帧之间合成中间帧，有效提高视频帧率。#### 2.9.1 RIFE（实时中间流量估计）
- **工作原理：** IFNet 直接估计中间光流，无需预先训练的光流模型。通过时间编码支持任意时间步插值。架构支持实时推理。
- **速度：** 比 SuperSlomo 和 DAIN 快 4-27 倍。
- **插值因子：** 可以生成 2x、4x、8x 或任意中间帧。
- **高尔夫的优势：** 将 30fps 转换为 240fps (8x) 将帧间位移控制在可管理的范围内。在 30 fps 下，时速 100 英里的球杆头每帧移动约 67 像素。在合成 240 fps 时，该值下降至约 8 像素/帧——完全在光流和跟踪器功能范围内。
- **限制：** 插值帧是综合估计，而不是真实的观察结果。插值本身依赖于运动估计，从而产生循环依赖性。非常快速且模糊的运动可能会产生伪影。插值质量会随着源帧之间较大的运动而降低。
- **链接：** [GitHub](https://github.com/hzwer/ECCV2022-RIFE)

#### 2.9.2 FILM（大运动帧插值）
- **工作原理：** 多尺度特征提取和流量估计，专为帧之间的大位移而设计。
- **高尔夫的优势：** 明确处理高尔夫挥杆中存在的大运动场景。比 RIFE 更适合极端的帧间位移。
- **链接：** [施普林格](https://link.springer.com/chapter/10.1007/978-3-031-20071-7_15)

#### 该项目的结论：
如果使用标准电话视频（30-60fps），帧插值是一个**关键的预处理步骤**。推荐的管道是：
1. 以手机的最大帧速率捕获视频（如果可用，理想情况下为 120-240 fps，最低 60 fps）
2.应用RIFE或FILM插值以获得更高的有效帧率
3. 在插值视频上运行点跟踪或光流
4. 请注意，插值帧的速度测量会带来额外的不确定性

**重要警告：** 插值位置是估计的，而不是测量的。插值帧的速度计算应被视为近似值，并根据已知速度的测试用例进行验证。

## 3. 速度计算数学深入研究

### 3.1 基本公式

视频速度的核心公式：```speed = distance_real / time_between_frames
```
其中：
- `distance_real` = 球杆头在帧之间移动的真实距离（米）
- `time_between_frames` = 1 / FPS（秒）

挑战是将像素位移转换为现实世界的距离。

### 3.2 像素位移到现实世界距离

#### 步骤 1：测量像素位移```displacement_pixels = sqrt((x2 - x1)^2 + (y2 - y1)^2)
```
其中（x1，y1）和（x2，y2）是连续帧中的球杆头位置（以像素为单位）。

#### 步骤 2：建立比例因子（每米像素）

**方法 A：已知参考对象**
将已知尺寸的物体放置在框架中与击球期间球杆头相同的深度平面处。```scale_factor = known_distance_pixels / known_distance_meters
```
示例：高尔夫球杆长约 45 英寸（1.143m）。在瞄准位置，测量球杆长度（以像素为单位）：```scale = club_length_pixels / 1.143  # pixels per meter
```
**方法 B：相机本征校准**
使用针孔相机模型：```distance_real = (displacement_pixels * Z) / f
```
其中：
- `Z` = 从相机到球杆头的距离（米）
- `f` = 焦距（像素） = focus_length_mm * (image_width_pixels /sensor_width_mm)

对于典型的智能手机：
- 传感器宽度：~6mm
- 焦距：~4.5mm
- 图像宽度：1920 像素
- f = 4.5 * (1920 / 6) = 1440 像素

如果球杆头距相机 3 米：```distance_real = (displacement_pixels * 3.0) / 1440
```
#### 步骤 3：计算速度```speed_m_per_s = distance_real / (1 / FPS)
speed_mph = speed_m_per_s * 2.237
```
### 3.3 完整示例计算

**设置：**
- 相机：iPhone，240fps，1080p
- 与高尔夫球手的距离：3米（测量）
- 球杆头在帧之间的位移：15 像素
- 焦距：1440像素（估计）```distance_real = (15 * 3.0) / 1440 = 0.03125 meters per frame
time_per_frame = 1/240 = 0.00417 seconds
speed = 0.03125 / 0.00417 = 7.5 m/s = 16.8 mph
```
等等——这太慢了。对于 240 fps 的 100 英里/小时摆动：```100 mph = 44.7 m/s
distance_per_frame = 44.7 * (1/240) = 0.186 meters
pixels_per_frame = 0.186 * 1440 / 3.0 = 89.3 pixels
```
因此，在 240 fps 下，球杆头以 100 英里/小时的速度每帧移动约 89 像素。在 30 fps 下，这将是约 715 像素——可能完全超出帧并产生极端模糊。

**关键见解：** 240fps 是跟踪 100 英里/小时以上球杆头的**最低可行帧速率**。在 120 fps 下，位移约为 179 像素/帧——可能但具有挑战性。在 30 fps 下，球杆头在单帧中穿过大部分帧，因此在没有插值的情况下几乎不可能进行跟踪。

### 3.4 透视校正和单应性

#### 问题
摄像机从固定角度观察秋千。球杆头在 3D 空间中移动，但相机捕获 2D 投影。朝向/远离相机的运动被压缩（缩短），并且角度运动被扭曲。

#### 单应性矩阵
单应性 `H` 是一个 3x3 矩阵，它将一个平面中的点映射到另一个平面中的对应点：```[x']     [h11 h12 h13] [x]
[y'] = H [h21 h22 h23] [y]
[w']     [h31 h32 h33] [1]
```
其中`(x'/w', y'/w')` 是校正后的坐标。

需要已知现实世界位置与其像素位置之间的 4 个以上点对应才能求解 H.

#### 高尔夫实用校准
1. 在挥杆平面地面上的已知位置放置标记
2. 根据这些对应关系计算单应性
3. 应用单应性将像素坐标转换为挥杆平面中的真实世界坐标

**OpenCV 实现：**```pythonH, status = cv2.findHomography(src_points, dst_points)
real_coords = cv2.perspectiveTransform(pixel_coords, H)
```
### 3.5 相机角度注意事项

#### 正面视图（正面）
- 摄像机从前方（目标线）面向高尔夫球手。
- 球杆头主要在画面中从左到右和从上到下移动。
- 深度移动（朝向/远离相机）被压缩。
- **修正：** 挥杆平面与垂直方向大约成 45-60 度。真实的 3D 位移大约为：```  distance_3D = distance_2D / cos(angle_out_of_plane)
  ```
对于与相机平面成 45 度的典型摆动平面：```  distance_3D = distance_2D / cos(45) = distance_2D * 1.414
  ```
#### 线下视图 (DTL)
- 摄像机沿着目标线放置在高尔夫球手身后。
- 看到挥杆平面几乎在边缘。
- 球杆头运动主要在摄像机平面内。
- **更适合速度测量**，因为需要较少的平面外校正。
- **校正系数：** 小得多，~1.0-1.1，具体取决于确切的摄像机角度。

#### 这个应用程序的推荐
**为了速度测量的准确性，首选线下视图**。摆动平面与相机图像平面更加对齐，减少了透视误差。如果使用正面，则根据高尔夫球手的挥杆平面角度应用约 1.3-1.5 的修正系数。

### 3.6 错误来源和缓解措施

|错误来源|幅度 |缓解措施 |
|---|---|---|
| **帧速率太低** |主导错误。在 30 fps 时，帧之间的球杆位置未知 |使用可用的最高 FPS（首选 240）。帧插值作为后备。 |
| **运动模糊** |球杆头变成细长条纹，质心不明确 |曝光时间短。使用条纹端点。图像去模糊预处理。 |
| **比例因子不正确** |正比例误差（10% 刻度误差 = 10% 速度误差） |多重参考测量。在瞄准时使用球杆长度。 |
| **相机距离不确定性** |通过针孔模型的比例误差 |测量相机距离。在较新的手机上使用 LiDAR 传感器来测量距离。 |
| **视角/角度误差** | 10-40% 取决于视角 |使用 DTL 视图。应用透视校正。使用已知标记进行校准。 |
| **卷帘快门** |手机 CMOS 传感器从上到下扫描，快速物体出现倾斜 |使用具有全局快门或快速滚动快门的手机。帖子中正确。 |
| **镜头畸变** |框架边缘 1-5% |应用相机校准（棋盘图案）以消除扭曲。 |
| **像素量化** |每次测量 +-0.5 像素 = 大位移时小 |通过光流或模板匹配进行子像素估计。 |
| **插值伪影** |未知——取决于运动和算法 |针对已知速度进行验证。仅使用插值作为增强，而不是主要测量。 |

### 3.7 建议的准确度目标

根据文献：
- GEARS商业系统：<0.2mm位置精度
- 立体相机+惯性传感器：平均精度~3.6cm
- 基于电话的 CV（本项目）：最初的目标是 +-5-10 英里/小时准确度，通过校准细化至 +-3 英里/小时

作为参考，100 英里/小时的驾驶员挥杆速度大约相当于：
- 球速：约 150 英里/小时（1.5 粉碎系数）
- 携带距离：约230码
- 球杆速度每变化 1 英里/小时 ~ 2.3 码距离

## 4. 摆动检测自动化

### 4.1 检测挥杆准备情况（挥杆前）

系统需要自动检测高尔夫球手何时准备好挥杆、开始记录/分析并识别挥杆阶段。#### 4.1.1 静止检测
- **方法：** 计算感兴趣区域上的帧差异或光流幅度。
- **阈值：** 当连续 N 帧的平均像素变化低于阈值时，高尔夫球手处于“静止”状态（击球位置）。
- **执行：**```  diff = abs(frame_current - frame_previous)
  motion_score = mean(diff[roi])
  if motion_score < threshold for N frames: still = True
  ```
#### 4.1.2 基于姿势的准备状态
- **方法：** 使用 MediaPipe Pose 检测高尔夫球手的身体标志（33 个关键点）。
- **“地址”位置的标准：**
  - 双手并拢（手腕关键点靠在一起）——检测到握力
  - 手臂向下伸展（肘部角度 > 150 度）
  - 躯干稍微向前弯曲（髋-肩-膝角度）
  - 双脚分开与肩同宽（脚踝关键点分离）
  - 头向下看（鼻子关键点低于肩膀关键点）
- **实施：**```python  import mediapipe as mp
  pose = mp.solutions.pose.Pose()
  results = pose.process(frame_rgb)
  wrist_dist = distance(results.pose_landmarks[15], results.pose_landmarks[16])
  if wrist_dist < grip_threshold: grip_detected = True
  ```
#### 4.1.3 组合方法（推荐）
1.检测画面中的人（YOLO或MediaPipe）
2. 验证姿势是否匹配“瞄准的高尔夫球手”（姿势估计）
3. 确认静止1-2秒（帧差分）
4. 装备摆动检测器

### 4.2 检测摆动开始（后摆开始）

#### 4.2.1 运动起始帧差分
- **方法：** 计算连续帧之间的绝对差。当静止一段时间后运动得分超过阈值时，摆动就开始了。
- **执行：**```  motion = sum(abs(frame[t] - frame[t-1])) / num_pixels
  if was_still and motion > onset_threshold: swing_started = True
  ```
- **细化：** 使用移动平均值来避免噪声的错误触发：```  smoothed_motion = moving_average(motion_scores, window=5)
  ```
#### 4.2.2 手腕速度检测
- **方法：** 通过 MediaPipe 跟踪手腕关键点。计算速度（每帧的像素位移）。后摆开始 = 当手腕速度在静止后首次超过阈值时。
- **优点：** 比全帧差分更具体。忽略不相关的运动（风、其他人）。

### 4.3 检测摆动阶段

基于 SwingNet (GolfDB)，规范的八个阶段是：

1. **地址** -- 静止，高尔夫球手在准备时
2. **脚趾向上** -- 球杆杆身与地面平行（后摆）
3. **中后挥杆** -- 球杆与脚趾向上约成 45 度角
4. **顶部** -- 最大后摆位置（最小手腕速度，方向反转）
5. **中下挥杆** -- 球杆杆身与地面平行（下挥杆）
6. **冲击**——球杆接触球（最大速度点）
7. **中随击**——球杆杆身与地面平行（随击）
8. **完成**——挥杆完成，高尔夫球手处于完成位置

####检测方法：
- **速度极值：** 上杆顶部 = 手腕/手速度的局部最小值。影响=局部最大值。
- **方向反转：** 跟踪手部运动的 x 分量。上杆向一个方向移动，下杆则相反。
- **肩部旋转：** 跟踪肩部关键点。肩膀和臀部之间的最大旋转差表示上杆的顶部。

### 4.4 检测摆动完成

#### 4.4.1 速度下降
- 击球后，球杆在后续动作中减速。
- **检测：** 当手/手腕速度在超过冲击速度后降至阈值以下时，挥杆完成。
- **执行：**```  if velocity > impact_threshold: impact_detected = True
  if impact_detected and velocity < completion_threshold: swing_complete = True
  ```
#### 4.4.2 基于姿势的完成检测
- MediaPipe 检测“完成”姿势：
  - 双手高举（手腕关键点高于肩膀）
  - 前脚重量（前脚踝关键点更低/更重）
  - 躯干完全转向目标
  - 臀部面向目标线

#### 4.4.3 归静
- 跟进后，高尔夫球手返回到静止位置。
- 与预挥杆相同的静止检测，但在冲击检测之后应用。

### 4.5 动态场景的背景建模

#### 4.5.1 自适应背景模型
对于有风、其他高尔夫球手和光线变化的室外练习场：```pythonbg_subtractor = cv2.createBackgroundSubtractorMOG2(
    history=500,       # frames for background model
    varThreshold=50,   # sensitivity (lower = more sensitive)
    detectShadows=True
)

# For each frame:
fg_mask = bg_subtractor.apply(frame)
# Apply morphological operations to clean up:
fg_mask = cv2.morphologyEx(fg_mask, cv2.MORPH_OPEN, kernel)  # remove noise
fg_mask = cv2.morphologyEx(fg_mask, cv2.MORPH_CLOSE, kernel)  # fill gaps
```
#### 4.5.2 基于 ROI 的处理
而不是处理整个帧：
1.检测高尔夫球手的边界框（YOLO或姿势估计）
2. 定义高尔夫球手周围的“挥杆区”ROI
3. 仅在此 ROI 内应用背景扣除和运动分析
4. 减少后台活动的计算量和误报

### 4.6 推荐的摆动检测管道```1. CONTINUOUS MONITORING PHASE
   - Run MediaPipe Pose at reduced resolution (320x240) for efficiency
   - Detect person in frame
   - Check for "golfer at address" pose

2. READY DETECTION
   - Pose matches address position
   - Stillness confirmed (< 2 seconds of no motion)
   - Begin high-resolution capture / buffer last N seconds

3. SWING ONSET
   - Frame differencing exceeds threshold after stillness
   - OR wrist velocity exceeds threshold
   - Begin tracking club head position

4. SWING TRACKING
   - Track club head through backswing, downswing, impact, follow-through
   - Record position at each frame
   - Identify impact frame (maximum velocity)

5. SWING COMPLETION
   - Velocity drops below threshold after impact
   - OR finish pose detected
   - OR return to stillness

6. SPEED CALCULATION
   - Compute displacement between frames surrounding impact
   - Apply scale factor and perspective correction
   - Report speed in mph
```

## 本项目的建议摘要

### 最有前途的技术方法（排名）

1. **点跟踪 (TAPIR/CoTracker) + 卡尔曼滤波器** -- 通过挥杆跟踪球杆头上特定点的最佳准确度潜力。处理遮挡。需要 GPU 进行推理（可接受离线处理）。

2. **姿势估计 (MediaPipe) + 手腕速度代理** -- 跟踪手/手腕位置作为球杆头速度的代理（由于杠杆效应，手腕速度 ~ 0.4-0.5x 球杆头速度）。在移动设备上实时工作。不太准确但可以立即部署。

3. **帧插值（RIFE）+光流（RAFT）** -- 将30/60fps视频插值到240fps有效，然后使用RAFT密集光流测量位移。精度高，但需要大量计算。

4. **YOLO自定义检测+卡尔曼滤波器** -- 训练一个小型YOLO模型来检测球杆头，使用卡尔曼滤波器进行帧间预测。需要标记的训练数据。

5. **背景扣除+轮廓分析**——最简单的方法。通过MOG2隔离移动的球杆，找到移动速度最快的轮廓端点。最不准确，但无需 ML 模型即可工作。

### 关键帧速率要求
|第一人称射击 |球杆头像素/帧（100 英里/小时，3m 距离）|生存能力|
|-----|------------------------------------------|------------|
| 30| ~715 像素 |没有插值就无法实现 |
| 60| ~358 像素 |边际，需要插值 |
| 120 | 120 ~179 像素 |可与高级追踪器配合使用 |
| 240 | 240 ~89 像素 |适用于大多数跟踪方法 |
| 480 | 480 ~45 像素 |优秀的，即使是简单的方法也有效 |

  -> RIFE Frame Interpolation (if < 240fps)
