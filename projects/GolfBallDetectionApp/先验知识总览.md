## 二、未实现但研究文档已论证的优化方向

### 2.1 YOLO CoreML 球检测（优先级：高）

**现状**：训练脚本已写好（`tools/train_ball_detector/`），但没有训练数据和模型文件。当前仅帧差分路径工作。

**研究结论**（来源：`iPhone球轨迹追踪竞品分析.md` 3.4 节）：
- YOLO11n 在 iPhone 17 Pro Max Neural Engine 上约 5ms/帧 → 240fps 逐帧分析完全可行
- 模型仅 ~6MB，适合移动端
- Roboflow 上有多个预标注高尔夫球数据集（500+ 张）

**实施路径**：
```
Roboflow 数据集（YOLO 格式）
  → YOLO11n 训练（~100 epochs, imgsz=640）
  → model.export(format='coreml', nms=True)
  → best.mlpackage 拖入 Xcode
  → VNCoreMLRequest 推理
  → 集成到 FusedBallDetector（YOLO 优先 + 帧差分回退）
```

**验证指标**：mAP@0.5 > 0.85，天空背景检测率 > 95%，草地背景 > 80%

### 2.2 LiDAR 距离标定（优先级：高）

**现状**：`BallDetectionViewModel.swift` 中 `pixelsPerMetre: 200` 是硬编码占位值。

**研究结论**（来源：`轨迹预测可借鉴分析.md` 5.2 节 + `iPhone球轨迹追踪竞品分析.md` 2.1 节）：
- iPhone LiDAR 有效范围 ~5m，3-5m 场景在有效范围内
- 标定公式：`实际位移 = 像素位移 × 距离 / (焦距 × 像素密度)`
- PiTrac `gs_calibration.h` 提供了完整的标定流程参考

**实施路径**：
```
LiDAR 测量手机到球距离 d（pre-shot）
  + iPhone 相机内参（焦距 f，可从 AVCaptureDevice 获取）
  → pixelsPerMetre = f × 像素密度 / d
  → 替换硬编码值
```

**精度预期**：
| 距离 | 1 像素对应 | 杆头位置精度 |
|------|----------|------------|
| 3m | ~1.6mm | ±2-3mm |
| 5m | ~2.6mm | ±3-5mm |

### 2.3 音频击球检测增强（优先级：中）

**现状**：`SwingAudioDetector.swift` 已有基础音频击球检测。

**研究结论**（来源：`轨迹预测可借鉴分析.md` 3.3 节）：
golf-clip 的 SuperFlux + 多特征加权评分比简单能量阈值更鲁棒：
```
频谱质心（目标 3500Hz）× 30%
+ 衰减比（越低越好）× 30%
+ RMS 能量 × 25%
+ 频谱平坦度 × 15%
= 置信度评分（> 0.3 保留）
```

**移植建议**：用 Apple Accelerate vDSP 重实现 Essentia.js 的 SuperFlux 算法。

### 2.4 间接+直接球速融合（优先级：中）

**现状**：当前仅通过杆头速度 × Smash Factor 间接推算球速。

**研究结论**（来源：`轨迹预测可借鉴分析.md` 五-阶段4 + `iPhone球轨迹追踪竞品分析.md` 2.1 节）：
```
间接推算：杆头速度 × Smash Factor → 球速（已实现）
直接追踪：击球后 2-5 帧球位移 → 球速（未实现）
融合：按各自置信度加权 → 更高精度
```

**GolfTrak 方案参考**：
- 手机放球后方 ~50cm，球在画面中 50-100 像素直径
- 240fps 下球速 150mph → 每帧移动 ~28cm
- 追踪击球后前 2-5 帧即可计算球速

**本项目场景差异**：3-5m 侧面视角，球更小（3-20 像素），但 KalmanFilter6D 已有重力模型可辅助追踪。

### 2.5 Strokes Gained 评估（优先级：低）

**现状**：未实现。

**研究结论**（来源：`reference_code/README.md` — GoBirdie app.js）：

- `computeStrokesGained()` + `interpolateBaseline()` 线性插值

**借鉴价值**：可增强 InsightEngine 的分析深度，但需要 GPS 落点数据。

### 2.6 MobileSAM CoreML 集成（优先级：低，依赖未解决）

**现状**：标记为待办，模型转换依赖未解决。

## 三、关键物理量推导链

```
杆头速度 (club head speed)
  ↓ × Smash Factor（球杆类型相关，Driver 1.49, 7I 1.29）
球速 (ball speed)
  ↓ + 发射角 (launch angle) + 旋转率 (spin rate)
初始飞行向量
  ↓ + 空气阻力 (Cd=0.25) + Magnus 效应 (Cl=0.18) + 重力
飞行轨迹 (trajectory)
  ↓ + 环境修正（风/海拔/温度 → 空气密度 ρ）
预测落点 (landing point)
```

### 3.5 弹道方程核心参数

```
球物理常量：
  质量 m = 0.04593 kg
  半径 r = 0.02135 m
  截面积 A = π × r² ≈ 0.00143 m²
  阻力系数 Cd = 0.25（有酒窝）
  升力系数 Cl = 0.18（基准值，随旋转参数缩放）

空气密度：
  海平面标准 ρ₀ = 1.225 kg/m³（15°C）
  海拔修正 ρ(h) = ρ₀ × exp(-h / 8500)
  温度修正 ρ(T) = P / (R × T)  （T 为绝对温度 K）

数值积分：
  方法：4 阶 Runge-Kutta
  步长 dt = 0.001s
  最大飞行时间 = 15s
  终止条件：y ≤ 0 且 t > 0.1s
```

## 五、两大技术路线对比

研究文档识别了市场上两种主要技术路线：

### 路线 A：手机端发射监测器（Launch Monitor）

代表产品：GolfTrak、GolfBoy

```
手机放球后方（~50cm）→ 实时球检测 → 击球检测（球消失/位置突变/音频）
  → 240fps 缓冲区回溯 → 击球后 2-5 帧球追踪
  → 像素位移 × 标定系数 / 帧间时间 = 球速
  → atan2(垂直位移, 水平位移) = 发射角
  → 物理模型外推 → carry 距离 + 落点
```

优势：球近（50-100 像素直径），标定简单，精度高（球速 ±3-5%）
劣势：需弯腰放手机，使用不便

### 路线 B：视频弹道叠加（Shot Tracer）

代表产品：Shot Tracer、ShotCatch

```
录制视频（30/240fps）→ 逐帧球检测（背景差分/YOLO/CNN）
  → Kalman Filter 帧间关联 → 处理遮挡/模糊/丢失
  → 离散点 → 样条/Bezier 曲线拟合（物理约束：重力抛物线）
  → 视频帧上渲染轨迹线（辉光效果、渐变色）
```

优势：架好三脚架即可，适合社交分享
劣势：球远（3-10 像素），标定复杂，距离不精确

### 本项目定位

本项目采用路线 B 的视角（3-5m 侧面），但融合路线 A 的间接推算能力（杆头速度 × Smash Factor），形成独特的融合方案。

## 六、精度预期与风险

### 6.1 3-5m 距离的精度限制

| 因素 | 影响 | 量化 |
|------|------|------|
| 像素分辨率 | 3m 下 1px ≈ 1.6mm；5m 下 1px ≈ 2.6mm | 杆头位置精度 ±2-5mm |
| 运动模糊 | 杆头 100mph 时 1/240s 曝光 → 模糊 ~186mm | 需运动模糊分析补偿 |
| 深度信息缺失 | 2D 视频无法直接获取深度 | SwingPlaneCorrector 部分补偿 |
| LiDAR 范围 | iPhone LiDAR 有效 ~5m，3-5m 在边界 | 深度精度 ±1-3cm |
| 杆头速度精度 | 2D 追踪 + 3D 修正后 | 估计 ±5-10% |

### 6.2 旋转率无法直接测量

- 旋转率对弹道影响巨大（倒旋决定高度，侧旋决定弯曲）
- 普通视频无法测量（需 Doppler 雷达如 TrackMan）
- 缓解方案：球杆类型查表 + 杆头速度修正 + 杆面角度推断
- 精度预期：旋转率估算误差 ±20-30%，导致落点距离误差 ±10-15%

### 6.3 各参数精度对比

| 参数 | GolfTrak（球后50cm） | 本项目（侧面3-5m） |
|------|---------------------|-------------------|
| 球速 | ±3-5% | ±5-10% |
| 发射角 | ±1-2° | ±2-4° |
| carry 距离 | ±5-10% | ±10-20% |
| 侧偏方向 | ±2-3° | ±3-5° |

### 6.4 环境修正已知问题

| 问题 | 来源 | 处理 |

## 八、下一步开发优先级建议

### 立即可做（无外部依赖）

1. **macOS 命令行验证工具** — 读取视频 → 帧差分检测 → 速度计算 → 弹道预测 → 终端输出。用真实高尔夫视频验证整条链路，发现需要调参的地方。

2. **帧差分检测参数调优** — 当前阈值（diffThreshold=25, minBlobArea=9, maxBlobArea=400, minCircularity=0.6）基于合成测试帧，需在真实视频上验证和调整。

### 短期（1-2 周）

3. **YOLO CoreML 球检测模型训练** — Roboflow 数据集 + YOLO11n + CoreML 导出。这是从"帧差分 only"到"双路径融合"的关键一步。

4. **LiDAR 距离标定** — 替换硬编码 `pixelsPerMetre: 200`，让速度和距离计算有物理意义。

### 中期（2-4 周）

5. **击球后球直接追踪** — 扩展 BallTrackingPipeline，在击球后 2-10 帧追踪球的初始飞行，直接测量球速。

6. **间接+直接球速融合** — 杆头速度×Smash Factor + 球初始飞行追踪 → 加权融合。

### 长期

7. **音频击球检测增强** — SuperFlux + 多特征评分。
8. **Strokes Gained 评估** — SG 基线表 + NLG 洞察。
9. **OpenWeather API 集成** — 实时天气 → 环境修正。
