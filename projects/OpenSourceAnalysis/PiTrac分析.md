# PiTrac 项目分析（iPhone 17 Pro Max 可用性评估）

> 仓库：`PiTracLM/PiTrac`
> 语言：C++ (OpenCV)
> 定位：DIY 高尔夫发射监测器 — 双摄像头立体视觉测量球速、发射角、旋转率
> 来源：https://github.com/PiTracLM/PiTrac

## 一、项目概述

PiTrac 是一个开源 DIY 高尔夫发射监测器（Launch Monitor），使用低成本 Raspberry Pi 和双摄像头硬件，通过立体视觉和图像处理算法测量高尔夫球的：
- **球速**（Ball Speed）
- **发射角**（Launch Angle — 垂直）
- **方位角**（Azimuth — 水平偏移）
- **旋转率**（Spin Rate — 倒旋和侧旋）

### 技术栈

| 组件 | 技术 |
|------|------|
| 语言 | C++ |
| 图像处理 | OpenCV |
| 硬件 | Raspberry Pi 4/5 + 双 Pi Camera（IR 滤镜移除） |
| 照明 | IR 频闪灯（击球触发） |
| 触发 | 压电传感器或麦克风检测击球 |
| 通信 | WiFi → 手机/PC 显示结果 |
| 构建 | CMake |

### 核心测量原理

```
双摄像头（立体视觉）
  ├── Camera 1：侧视角，捕获球的水平运动
  ├── Camera 2：俯视角或另一侧视角，捕获球的垂直运动
  └── 两个摄像头同步曝光（IR 频闪）
        ↓
击球触发（压电/麦克风）
  → 频闪曝光（2-3 次闪光，间隔已知）
  → 每次闪光在传感器上留下球的影像
        ↓
图像处理
  ├── 球检测：在每帧中找到球的位置（圆形检测）
  ├── 多次曝光：同一帧中球出现 2-3 个位置
  ├── 位移计算：相邻曝光之间的像素位移
  └── 速度 = 位移 × 标定系数 / 闪光间隔
        ↓
3D 重建
  ├── 立体三角测量：两个摄像头的 2D 位置 → 3D 坐标
  ├── 发射角 = atan2(垂直位移, 水平位移)
  ├── 方位角 = atan2(横向位移, 前向位移)
  └── 旋转率 = 球表面标记的旋转角度 / 时间
```

## 二、核心算法详解

### 2.1 球检测算法

PiTrac 使用 OpenCV 的图像处理管线检测高尔夫球：

```
输入：IR 频闪照明下的灰度图像
  ↓
预处理：
  1. 高斯模糊降噪
  2. 自适应阈值二值化（区分球和背景）
  3. 形态学操作（开运算去噪 + 闭运算填充）
  ↓
球检测：
  方法 A：HoughCircles 圆检测
    - 参数：最小/最大半径、累加器阈值、最小距离
    - 优点：直接检测圆形
    - 缺点：参数敏感，假阳性多
  
  方法 B：轮廓检测 + 圆度筛选
    - findContours → 计算面积和周长
    - 圆度 = 4π × 面积 / 周长²（完美圆 = 1.0）
    - 筛选：圆度 > 0.7 且面积在合理范围内
    - 优点：更鲁棒
  ↓
多次曝光匹配：
  同一帧中检测到多个球位置（频闪产生）
  按位置排序 → 确定运动方向 → 计算位移向量
```

#### 对 iPhone 移植的借鉴

- **圆形检测**：iPhone 可用 Vision VNDetectCirclesRequest 或 Core Image CIDetector
- **轮廓检测**：可用 Vision VNDetectContoursRequest
- **关键差异**：PiTrac 用 IR 频闪（球在黑暗背景上非常明亮），iPhone 用自然光（需要更复杂的检测）
- **本仓库已有更好方案**：`GolfBallDetectionApp` 使用 YOLO CoreML 模型检测球

### 2.2 球速计算

```
球速计算原理：

已知：
  - 频闪间隔 Δt（例如 10μs = 0.00001s）
  - 像素位移 Δpx（两次曝光之间球移动的像素数）
  - 标定系数 K（像素 → 实际距离，通过标定板获得）

计算：
  实际位移 Δd = Δpx × K  （米）
  球速 v = Δd / Δt  （米/秒）
  球速 mph = v × 2.237

精度分析：
  - 频闪间隔精度：±1μs → 速度误差 ±0.01%（可忽略）
  - 像素定位精度：±0.5px → 取决于标定系数
  - 标定精度：通过棋盘格标定，典型精度 ±1-2%
  - 综合精度：±2-3%（与 TrackMan 对比）
```

#### 对 iPhone 移植的借鉴

- **频闪方法不可用**：iPhone 没有 IR 频闪灯，无法在单帧中产生多次曝光
- **替代方案**：iPhone 用 240fps 慢动作，每帧之间的时间间隔 = 1/240s ≈ 4.17ms
- **本仓库已有**：`SpeedCalculator.swift` 使用帧间追踪 + 运动模糊分析计算杆头速度
- **可借鉴**：标定系数的概念 — 需要知道相机到球的距离才能将像素位移转换为实际距离

### 2.3 发射角和方位角计算

```
3D 三角测量：

Camera 1 检测到球在 (x1, y1) 位置
Camera 2 检测到球在 (x2, y2) 位置

通过立体视觉标定（已知两个摄像头的相对位置和内参）：
  → 三角测量得到球的 3D 坐标 (X, Y, Z)

对两次曝光分别做 3D 重建：
  曝光 1：球在 (X1, Y1, Z1)
  曝光 2：球在 (X2, Y2, Z2)

运动向量：
  ΔX = X2 - X1  （横向）
  ΔY = Y2 - Y1  （垂直）
  ΔZ = Z2 - Z1  （前向/目标方向）

发射角（垂直）：
  launch_angle = atan2(ΔY, √(ΔX² + ΔZ²))
  典型范围：10°-35°

方位角（水平偏移）：
  azimuth = atan2(ΔX, ΔZ)
  典型范围：-15° ~ +15°
  正值 = 右偏（fade/slice），负值 = 左偏（draw/hook）
```

#### 对 iPhone 移植的借鉴

- **立体视觉不可用**：iPhone 只有一个后置广角摄像头用于录制
- **LiDAR 替代**：iPhone 17 Pro Max 有 LiDAR，可提供深度信息，但有效范围 ~5m
- **单目替代方案**：
  - 从已知球大小（直径 42.67mm）推算距离
  - 从 2D 运动方向 + 挥杆平面模型推算 3D 发射角
  - 本仓库 `SwingPlaneCorrector.swift` 已实现类似的 2D→3D 恢复
- **可借鉴**：3D 向量分解为发射角和方位角的数学方法

### 2.4 旋转率估算

```
旋转率测量原理（PiTrac 方法）：

前提：球上有可识别的标记（如品牌 logo、对齐线）

方法：
  1. 在两次频闪曝光中检测球表面标记的位置
  2. 计算标记的旋转角度 Δθ
  3. 旋转率 = Δθ / Δt（度/秒 → rpm）

实际挑战：
  - 球表面标记在高速运动中模糊
  - 需要高分辨率 + 短曝光时间
  - PiTrac 使用 IR 频闪（~10μs 曝光）冻结运动
  - 即使如此，旋转率测量精度远低于球速

PiTrac 的旋转率精度：
  - 倒旋：±500-1000 rpm（TrackMan 精度 ±50 rpm）
  - 侧旋：难以可靠测量
  - 这是 PiTrac 最薄弱的环节
```

#### 对 iPhone 移植的借鉴

- **直接测量不可行**：iPhone 240fps 曝光时间 ~4ms，球速 150mph 时球移动 ~270mm/帧，严重运动模糊
- **间接估算更实际**：
  - 从球杆类型查表（本文档 轨迹预测可借鉴分析.md 2.3 节）
  - 从杆面角度和挥杆路径推断侧旋方向
  - 从杆头速度修正旋转率范围
- **PiTrac 的经验**：即使专用硬件，旋转率也是最难测量的参数 → 验证了我们用查表法的合理性

### 2.5 相机标定

```
PiTrac 标定流程：

1. 内参标定（每个摄像头独立）：
   - 使用棋盘格标定板
   - 多角度拍摄 20+ 张图片
   - OpenCV calibrateCamera() → 焦距、主点、畸变系数
   
2. 外参标定（双摄像头相对位置）：
   - 两个摄像头同时拍摄棋盘格
   - OpenCV stereoCalibrate() → 旋转矩阵 R、平移向量 T
   
3. 距离标定（像素 → 实际距离）：
   - 在已知距离放置标定物
   - 计算标定系数 K = 实际距离 / 像素距离
   
4. 频闪标定：
   - 使用示波器测量实际频闪间隔
   - 确保间隔精度 < ±1μs
```

#### 对 iPhone 移植的借鉴

- **内参已知**：iPhone 摄像头内参可通过 AVCaptureDevice 获取（焦距、像素大小）
- **距离标定是关键**：
  - PiTrac 固定安装，距离已知
  - iPhone 手持，距离 3-5m 变化
  - 需要实时距离估算：LiDAR / 已知球大小 / 人体身高参考
- **可借鉴**：标定系数的概念和计算方法

### 3.2 PiTrac vs iPhone 方案对比

| 方面 | PiTrac | iPhone 17 Pro Max |

| 运动模糊 | 极小（频闪冻结） | 严重（球速 150mph → 270mm/帧） |
| 3D 信息 | 立体视觉（精确） | LiDAR（~5m 范围）或单目估算 |

| 发射角精度 | ±1-2° | ±3-5°（估计） |
| 旋转率 | 可测量（精度低） | 无法直接测量（查表） |
| 安装 | 固定位置 | 手持/三脚架 |

| 便携性 | 低（需要安装） | 高（随身携带） |

### 3.3 PiTrac 验证了的关键结论

1. **旋转率是最难测量的参数**：即使专用硬件也只能达到 ±500-1000 rpm 精度，验证了我们用球杆类型查表的策略
2. **标定是精度的关键**：像素→距离的转换精度直接决定球速精度
3. **运动模糊是主要挑战**：PiTrac 用频闪解决，iPhone 需要运动模糊分析（本仓库 `SpeedCalculator.speedFromMotionBlur()` 已实现）
4. **3D 重建需要深度信息**：单目视觉无法直接获取深度，需要先验知识（球大小、人体身高、挥杆平面模型）

## 六、深度可行性分析

### 6.1 PiTrac 测量精度 vs iPhone 预期精度

| 参数 | PiTrac 精度 | iPhone 预期精度 | 差距原因 |
|------|-----------|---------------|---------|
| 球速 | ±2-3% | ±5-10% | iPhone 无频闪，依赖帧间追踪 |
| 发射角 | ±1-2° | ±3-5° | iPhone 单目，缺乏深度信息 |
| 方位角 | ±1-2° | ±5-10° | 同上 |
| 倒旋 | ±500-1000 rpm | 查表（±20-30%） | iPhone 无法直接测量旋转 |
| 侧旋 | 不可靠 | 推断方向（无量化） | 两者都困难 |

### 6.2 从 PiTrac 学到的关键教训

1. **频闪是核心创新**：PiTrac 的精度主要来自 IR 频闪（等效 100,000fps），而非算法复杂度。iPhone 没有这个硬件优势，必须用更智能的算法补偿。

2. **标定决定一切**：PiTrac 花大量精力在标定上（棋盘格、已知距离、频闪间隔）。iPhone 方案同样需要精确的距离标定。

3. **旋转率是天花板**：即使 PiTrac 也承认旋转率测量是最薄弱的环节。这验证了我们用查表法的策略——不要试图从视频直接测量旋转率。

4. **简单物理模型足够**：PiTrac 的球速计算本质上就是 `距离/时间`，没有复杂的机器学习。iPhone 方案也应该优先使用物理模型，ML 作为补充。

### 6.3 iPhone 方案的独特优势

虽然 PiTrac 在硬件精度上占优，但 iPhone 方案有独特优势：

| 优势 | 说明 |
|------|------|
| 人体姿态分析 | Vision 3D Pose（17 个关节点）→ 挥杆分析、杆头速度推算 |
| 挥杆全过程 | 240fps 录制完整挥杆（PiTrac 只捕获击球瞬间） |
| 环境感知 | GPS、气压计、天气 API → 环境距离修正 |
| 便携性 | 随身携带，无需安装 |
| 用户界面 | 原生 iOS App，实时反馈 |
| 数据积累 | 长期记录 → 个性化模型 → 精度逐步提升 |
