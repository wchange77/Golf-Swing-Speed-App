# 3-5 米距离球轨迹预测 — 开源项目可借鉴内容分析

> 目标场景：iPhone 17 Pro Max 距离球员 3-5 米，通过人体姿态 + 球杆 + 球，推断高尔夫球的飞行轨迹和落点
> 分析对象：golf-clip、GoBirdie-Desktop、ClubUp、PiTrac 四个开源项目 + 本仓库已有代码

## 一、任务定义

### 1.1 场景描述

```
相机位置：距离球员 3-5 米（正面或侧面）
录制参数：240fps @ 1080p（iPhone 17 Pro Max 慢动作）
可选传感器：LiDAR（深度信息）、麦克风（击球声）、GPS（位置）、气压计（海拔）

输入信号：
  ├── 人体姿态 → Vision VNDetectHumanBodyPose3DRequest（17 个 3D 关节点）
  ├── 球杆信息 → 杆头追踪（YOLO + Kalman）+ 杆身线段检测 + 球杆类型
  ├── 球信息 → 球检测（初始位置）+ 击球时刻（音频/视觉）
  └── 环境信息 → GPS（海拔）+ 天气 API（风速/温度/降雨）

输出：
  ├── 球飞行轨迹（3D 曲线：x=横向, y=高度, z=纵深/距离）
  ├── 预测落点（GPS 坐标或相对距离+方向）
  ├── 弹道参数（球速、发射角、最高点、飞行时间、落地角）
  └── 弹道形状分类（straight/draw/fade/hook/slice）
```

### 1.2 关键物理量推导链

```
杆头速度 (club head speed)
  ↓ × Smash Factor（球杆类型相关）
球速 (ball speed)
  ↓ + 发射角 (launch angle) + 旋转率 (spin rate)
初始飞行向量
  ↓ + 空气阻力 + Magnus 效应 + 重力
飞行轨迹 (trajectory)
  ↓ + 环境修正（风/海拔/温度）
预测落点 (landing point)
```

## 二、轨迹预测物理模型

### 2.1 从杆头速度到球速 — Smash Factor

**Smash Factor** = 球速 / 杆头速度，反映能量传递效率。

| 球杆类型 | 典型杆头速度 (mph) | Smash Factor | 典型球速 (mph) | 来源 |
|---------|-------------------|-------------|---------------|------|
| Driver | 100 | 1.48-1.50 | 148-150 | TrackMan |
| 3-Wood | 95 | 1.44-1.46 | 137-139 | TrackMan |
| 5-Iron | 85 | 1.33-1.35 | 113-115 | TrackMan |
| 7-Iron | 80 | 1.28-1.30 | 102-104 | TrackMan |
| 9-Iron | 75 | 1.23-1.25 | 92-94 | TrackMan |
| PW | 72 | 1.20-1.22 | 86-88 | TrackMan |
| SW | 68 | 1.12-1.15 | 76-78 | TrackMan |

**本仓库已有**：`SpeedCalculator.swift` 可计算杆头速度（帧间追踪 + 运动模糊 + 多帧回归融合）。
**需新增**：Smash Factor 查表，按球杆类型映射。

### 2.2 发射角估算

发射角由三个因素决定：

```
发射角 ≈ 杆面倾角(loft) - 攻击角(attack angle) × 0.7 + 动态杆面角修正

其中：
  杆面倾角：球杆固有属性（Driver 10.5°, 7-Iron 34°, SW 56° 等）
  攻击角：杆头在击球瞬间的垂直运动方向
    正值 = 向上击球（Driver 典型 +3° ~ +5°）
    负值 = 向下击球（Iron 典型 -3° ~ -5°）
  动态杆面角修正：击球时杆面实际角度与静态倾角的差异
```

**本仓库已有**：
- `LagAnalyser.swift` → `calculateShaftLeanAtImpact()` 可计算击球时杆身前倾角度
- 杆身前倾 > 0 意味着手在杆头前面（去杆面角效应），实际发射角低于静态杆面倾角
- `SwingPlaneCorrector.swift` → 3D 挥杆平面模型可推算攻击角

**典型发射角参考表**（TrackMan 数据）：

| 球杆 | 杆面倾角 | 典型攻击角 | 典型发射角 | 典型最高点 |
|------|---------|----------|----------|----------|
| Driver | 10.5° | +3° ~ +5° | 11° ~ 14° | 28-32 m |
| 3-Wood | 15° | 0° ~ -1° | 11° ~ 13° | 24-28 m |
| 5-Iron | 27° | -2° ~ -4° | 14° ~ 17° | 25-30 m |
| 7-Iron | 34° | -3° ~ -5° | 16° ~ 19° | 28-32 m |
| 9-Iron | 42° | -3° ~ -5° | 20° ~ 24° | 28-32 m |
| PW | 46° | -3° ~ -5° | 24° ~ 27° | 25-30 m |
| SW | 56° | -4° ~ -6° | 30° ~ 35° | 20-25 m |

### 2.3 旋转率估算

旋转率无法从普通视频直接测量（需要 Doppler 雷达如 TrackMan），但可以从球杆类型和杆头速度查表估算：

| 球杆 | 典型倒旋 (rpm) | 典型侧旋 (rpm) | 来源 |
|------|--------------|--------------|------|
| Driver | 2500-3000 | ±300-500 | TrackMan |
| 3-Wood | 3500-4000 | ±200-400 | TrackMan |
| 5-Iron | 5000-5500 | ±200-400 | TrackMan |
| 7-Iron | 6500-7500 | ±200-400 | TrackMan |
| 9-Iron | 8500-9500 | ±200-300 | TrackMan |
| PW | 9000-10000 | ±100-200 | TrackMan |
| SW | 9500-11000 | ±100-200 | TrackMan |

**侧旋方向判定**：
- 可从杆面角度（open/closed）和挥杆路径（in-to-out/out-to-in）推断
- `SwingPlaneCorrector.swift` 的 3D 模型可提供挥杆路径方向
- 侧旋 > 0 → fade/slice（右曲），侧旋 < 0 → draw/hook（左曲）

### 2.4 弹道方程

#### 简化模型（golf-clip 的 Bezier 方法）

golf-clip 使用二次 Bezier 曲线，不考虑物理：

```
B(t) = (1-t)²·P0 + 2(1-t)t·P1 + t²·P2

P0 = 击球原点
P2 = 落点
P1 = 2·apex - 0.5·(P0 + P2)  // 控制点，使曲线在 t=0.5 通过顶点

优点：计算简单，视觉效果好
缺点：不考虑空气阻力、旋转、风力，弹道形状不真实
```

#### 完整物理模型（推荐）

考虑空气阻力和 Magnus 效应的 3D 弹道方程：

```
状态向量：[x, y, z, vx, vy, vz]
  x = 横向（左右）
  y = 垂直（高度）
  z = 纵向（距离/目标方向）

微分方程：
  dvx/dt = -Cd × ρ × A × v × vx / (2m) + Fm_x / m
  dvy/dt = -Cd × ρ × A × v × vy / (2m) - g + Fm_y / m
  dvz/dt = -Cd × ρ × A × v × vz / (2m) + Fm_z / m

其中：
  Cd = 阻力系数 ≈ 0.25（高尔夫球，有酒窝）
  ρ = 空气密度 ≈ 1.225 kg/m³（海平面，15°C）
  A = 球截面积 = π × r² ≈ 0.00143 m²（r = 0.02135 m）
  m = 球质量 = 0.04593 kg
  v = 速度大小 = √(vx² + vy² + vz²)
  g = 重力加速度 = 9.81 m/s²
  Fm = Magnus 力（由旋转产生的升力/侧力）

Magnus 力：
  Fm = Cl × ρ × A × v² / 2
  Cl = 升力系数 ≈ 0.15-0.25（取决于旋转率和速度）
  方向：垂直于速度和旋转轴

数值积分：4 阶 Runge-Kutta，步长 dt = 0.001s
终止条件：y ≤ 0（球落地）
```

#### 两种模型对比

| 方面 | Bezier（golf-clip） | 物理模型 |
|------|-------------------|---------|
| 计算复杂度 | O(n)，n=采样点数 | O(T/dt)，T=飞行时间 |
| 输入参数 | 起点、落点、高度、形状 | 球速、发射角、旋转率 |
| 物理准确性 | 低（纯几何） | 高（考虑空气动力学） |
| 适用场景 | 视频叠加可视化 | 落点预测 |
| 环境因素 | 不支持 | 可集成（风/海拔/温度） |
| 实现难度 | 极低（~30 行代码） | 中等（~150 行代码） |

**建议**：两种模型都实现。Bezier 用于快速可视化预览，物理模型用于精确落点预测。

## 三、从开源项目可借鉴的算法（逐项详解）

### 3.1 golf-clip：Bezier 弹道生成

**来源**：`apps/browser/src/lib/trajectory-generator.ts` → `generateTrajectory()`

#### 完整代码逻辑中文解读

```
输入：落点坐标(归一化 0-1)、配置(高度/形状/飞行时间)、可选原点/顶点
  ↓
第一步：确定原点
  默认原点 = (0.5, 0.85)，即画面底部中央
  如果用户标记了击球位置，使用用户标记的坐标
  ↓
第二步：计算顶点
  顶点.x = (原点.x + 落点.x) / 2  ← 水平中点
  顶点.y = min(原点.y, 落点.y) - 高度乘数
  高度乘数：low=0.15, medium=0.25, high=0.35
  ↓
第三步：计算 Bezier 控制点
  控制点 = 2 × 顶点 - 0.5 × (原点 + 落点)
  数学保证：曲线在 t=0.5 时精确通过顶点
  ↓
第四步：采样曲线点
  采样数 = max(30, 飞行时间 × 60)
  对 t = 0 到 1 均匀采样：
    x(t) = (1-t)²×原点.x + 2(1-t)t×(控制点.x + 形状偏移×t) + t²×落点.x
    y(t) = (1-t)²×原点.y + 2(1-t)t×控制点.y + t²×落点.y
  注意：形状偏移随 t 线性增加，模拟 draw/fade 的渐进弯曲
```

#### 弹道参数表（中文翻译）

| 参数 | 英文 | 值 | 用途 |
|------|------|-----|------|
| 左曲球 | hook | -0.15 | 球大幅向左弯曲 |
| 小左曲 | draw | -0.08 | 球轻微向左弯曲 |
| 直球 | straight | 0 | 球直线飞行 |
| 小右曲 | fade | +0.08 | 球轻微向右弯曲 |
| 右曲球 | slice | +0.15 | 球大幅向右弯曲 |
| 低弹道 | low | 0.15 | 铁杆/低飞球 |
| 中弹道 | medium | 0.25 | 标准弹道 |
| 高弹道 | high | 0.35 | 高飞球/挖起杆 |

#### 对轨迹预测的借鉴价值

- **直接复用**：Bezier 曲线生成算法可作为快速可视化方案
- **参数映射**：形状偏移值（-0.15 ~ +0.15）可与侧旋率建立映射关系
- **高度乘数**：可与球杆类型关联（Driver → low/medium, Iron → medium, Wedge → high）
- **局限**：不考虑物理，仅适合可视化，不适合精确落点预测

### 3.2 golf-clip：球原点检测管线

**来源**：`apps/desktop/backend/detection/` 目录

#### 检测流程中文解读

```
输入：击球前后的视频帧
  ↓
第一步：YOLO 人体检测
  使用 ultralytics YOLO 模型检测画面中的人体
  输出：人体边界框 + 关键点
  iPhone 替代：Vision VNDetectHumanBodyPoseRequest（已在本仓库使用）
  ↓
第二步：杆身线段检测
  在人体下方区域进行 Hough 线段检测
  筛选条件：角度在合理范围内（接近垂直）、长度合理
  输出：杆身方向向量
  iPhone 替代：VNDetectContoursRequest 或自定义 Metal shader
  ↓
第三步：杆头颜色分析
  在杆身末端区域搜索杆头特征颜色（银色/黑色金属光泽）
  使用 HSV 颜色空间过滤
  输出：杆头位置
  iPhone 替代：Core Image 颜色过滤 + 本仓库 ClubHeadDetector（YOLO CoreML）
  ↓
第四步：击球原点定位
  杆头位置 + 杆身方向 → 推算球的初始位置
  球通常在杆面正前方、地面高度
  ↓
第五步：多特征评分
  综合 YOLO 置信度、线段检测质量、颜色匹配度
  输出：球原点坐标 + 置信度
```

#### 对轨迹预测的借鉴价值

- **球原点定位**：轨迹预测需要知道球的起始位置，这个管线提供了一种从视频推算的方法
- **杆身方向**：杆身方向在击球瞬间可推算杆面角度，进而推算发射角
- **本仓库已有更好方案**：`TrackingPipeline.swift` 已实现 YOLO + Vision + 光流 + 卡尔曼的杆头追踪

### 3.3 golf-clip：音频击球时刻检测

**来源**：`apps/browser/src/lib/audio-detector.ts` → `detectStrikes()`

#### 核心算法中文解读

```
输入：44100Hz 音频数据
  ↓
带通滤波 1000-8000Hz → 瞬态检测(SuperFlux) → 25s 去重
  ↓
对每个检测到的击球时刻，提取窗口特征：
  频谱质心（目标 3500Hz）× 30%
  + 衰减比（越低越好）× 30%
  + RMS 能量 × 25%
  + 频谱平坦度 × 15%
  = 置信度评分（> 0.3 保留）
```

#### 对轨迹预测的借鉴价值

- **精确 impact timestamp**：轨迹预测的起始时间点必须精确到毫秒级
- **本仓库已有**：`SwingAudioDetector.swift` 实现了音频击球检测
- **补充价值**：golf-clip 的多特征加权评分（质心+衰减比+能量+平坦度）比简单能量阈值更鲁棒
- **移植建议**：将 Essentia.js 的 SuperFlux 算法用 Apple Accelerate vDSP 重实现

### 3.5 GoBirdie：Haversine GPS 距离计算

**来源**：`src-tauri/src/models.rs` → `GpsPoint::distance_to()`

#### 代码逻辑中文解读

```rust
distance = R × 2 × atan2(√a, √(1-a))
// R = 6,371,000 米（地球平均半径）
// a = sin²(Δlat/2) + cos(lat1)·cos(lat2)·sin²(Δlon/2)
```

#### 对轨迹预测的借鉴价值

- **落点验证**：如果有 GPS 数据（球员位置 + 球落点位置），可计算实际飞行距离
- **与预测距离对比**：实际距离 vs 模型预测距离 → 评估模型精度
- **Swift 实现**：CoreLocation 已有 `CLLocation.distance(from:)` 使用相同算法

### 3.6 ClubUp：环境距离修正

**来源**：`ClubUp/ViewModel/DistanceCalcViewModel.swift`

#### 四个修正公式（中文解读 + 物理模型集成方式）

**风速修正**：
```
逆风：距离增加 0.5%/mph × 方向系数（注意：代码可能有 bug，见 ClubUp 分析文档）
顺风：距离减少 1%/mph × 方向系数

物理模型集成方式：
  不直接修正距离，而是在弹道方程中加入风速分量：
  dvx/dt += wind_x / m  （侧风）
  dvz/dt += wind_z / m  （顺/逆风）
  这比百分比修正更准确
```

**海拔修正**：
```
每 300 米海拔 → 球飞更远 1%（代码值，行业标准约 2%/305m）

物理模型集成方式：
  调整空气密度 ρ：
  ρ(h) = ρ₀ × exp(-h / 8500)
  其中 ρ₀ = 1.225 kg/m³，h = 海拔（米）
  海拔 600m → ρ ≈ 1.14 → 阻力减少 7% → 距离增加约 2%
```

**温度修正**：
```
每偏离 75°F 10 度 → ±2 码

物理模型集成方式：
  调整空气密度 ρ：
  ρ(T) = P / (R × T)
  其中 P = 大气压，R = 空气气体常数，T = 绝对温度(K)
  温度升高 → 空气密度降低 → 阻力减小 → 距离增加
```

**雨天修正**：
```
下雨 → 距离 +4%（球滚动减少）

物理模型集成方式：
  分两部分：
  1. 飞行距离：雨天空气密度略高（湿度影响小），基本不变
  2. 滚动距离：湿地面摩擦增大，滚动减少 → carry 不变但 total 减少
  建议：在落地后的滚动模型中减少滚动距离
```

#### 对轨迹预测的借鉴价值

- **环境因素意识**：提醒我们轨迹预测必须考虑环境因素
- **简化公式作为 fallback**：当无法获取精确气象数据时，可用这些经验公式
- **物理模型更优**：建议在弹道方程中直接调整空气密度，而非事后百分比修正

## 四、本仓库已有代码的复用

### 4.1 SwingPlaneCorrector — 3D 挥杆几何恢复

**文件**：`projects/HumanClubAnalysisApp/.../Features/SpeedCalc/SwingPlaneCorrector.swift`

**与轨迹预测的关系**：
- 从 2D 视频帧恢复 3D 挥杆平面几何
- 包含 TrackMan 数据的挥杆平面角度表（按球杆类型 48°-64.5°）
- 包含典型挥杆半径表（按球杆类型 1.22m-1.75m）
- `speedCorrectionFactor()` 可修正 2D 追踪速度到真实 3D 速度

**轨迹预测中的用途**：
1. 修正杆头速度（2D → 3D），这是球速推算的基础
2. 挥杆平面角度可推算攻击角（影响发射角）
3. 3D 杆头运动方向可推算杆面角度（影响侧旋方向）

**关键常量表**：

```swift
// 挥杆平面角度（度，从地面算起）— TrackMan 数据
SwingPlane.angles = [
    .driver: 48.0,      // 最平
    .threeWood: 51.0,
    .hybrid: 55.0,
    .fiveIron: 57.0,
    .sevenIron: 60.0,
    .pitchingWedge: 63.0,
    .sandWedge: 64.0,    // 最陡
]

// 典型挥杆半径（米，臂长+杆长）
SwingPlane.typicalSwingRadius = [
    .driver: 1.75,       // 最长
    .sevenIron: 1.45,
    .sandWedge: 1.25,    // 最短
]
```

### 4.2 SpeedCalculator — 杆头速度计算

**文件**：`projects/HumanClubAnalysisApp/.../Features/SpeedCalc/SpeedCalculator.swift`

**提供四种速度计算方法**：

| 方法 | 函数 | 精度 | 适用场景 |
|------|------|------|---------|
| 帧间差分 | `instantaneousSpeed()` | 中 | 基础速度，支持 2D 和 3D |
| 运动模糊 | `speedFromMotionBlur()` | 中 | 高速运动时补充 |
| 多帧回归 | `regressionSpeed()` | 高 | 最终速度估算（最小二乘拟合） |
| 融合速度 | `fusedSpeed()` | 最高 | 综合追踪+模糊，按置信度加权 |

**轨迹预测中的用途**：
- `impactSpeedMph` 是轨迹预测的核心输入
- 通过 Smash Factor 转换为球速
- 融合速度方法提供最可靠的杆头速度估算

### 4.3 TrackingPipeline — 杆头追踪

**文件**：`projects/HumanClubAnalysisApp/.../Features/Tracking/TrackingPipeline.swift`

**四层追踪架构**：

```
YOLO CoreML 检测（周期性重检测）
  ↓ 初始化/重置
Vision VNTrackObjectRequest（帧间追踪）
  ↓ 失败时
OpticalFlowTracker（光流追踪）
  ↓ 所有方法融合
KalmanFilter2D（预测+平滑，带杆长约束）
```

**轨迹预测中的用途**：
- 提供击球前后的杆头位置序列
- 杆头在击球瞬间的运动方向 → 推算球的初始飞行方向
- 可扩展为球追踪（击球后追踪球的初始飞行轨迹）

### 4.4 LagAnalyser — 释放角度分析

**文件**：`projects/HumanClubAnalysisApp/.../Features/LagAnalysis/LagAnalyser.swift`

**关键输出**：
- `shaftLeanAtImpact`：击球时杆身前倾角度 → 影响实际发射角
- `releasePointDegrees`：释放点 → 影响杆头速度峰值位置
- `lagRetentionIndex`：延迟保持指数 → 影响能量传递效率

**轨迹预测中的用途**：
- 杆身前倾 → 修正发射角（前倾越大，实际发射角越低于杆面倾角）
- 释放点 → 判断击球质量（早释放 = casting = 速度损失）
- 延迟保持 → 修正 Smash Factor（好的延迟 → 更高的 Smash Factor）

### 4.5 KalmanFilter2D — 球追踪（飞行中）

**文件**：`projects/HumanClubAnalysisApp/.../Features/Tracking/KalmanFilter.swift`

**当前用途**：追踪杆头
**可扩展用途**：追踪击球后飞行中的球

```
状态向量：[x, y, vx, vy]
预测模型：匀速运动 + 过程噪声
更新：检测到球时修正状态
约束预测：可加入重力约束（球必须沿抛物线运动）

扩展建议：
  1. 增加重力加速度到预测模型：vy' = vy - g × dt
  2. 增加空气阻力衰减：v' = v × (1 - k × dt)
  3. 用前几帧的追踪数据拟合弹道参数，然后外推预测落点
```

### 4.6 PostCaptureAnalysisEngine — 整体管线编排

**文件**：`projects/HumanClubAnalysisApp/.../Features/SpeedCalc/PostCaptureAnalysisEngine.swift`

**当前管线**：
```
视频 → 运动检测(30fps) → 相位分类 → 自适应帧选择
  → 3D 人体姿态(VNDetectHumanBodyPose3DRequest)
  → 杆头追踪(TrackingPipeline)
  → 速度计算(SpeedCalculator)
```

**轨迹预测扩展**：
```

  → 杆身前倾 + 球杆类型 → 发射角
  → 挥杆平面 + 杆面角 → 侧旋方向
  → 球杆类型查表 → 旋转率
  → 弹道方程积分 → 飞行轨迹
  → 环境修正(ClubUp 公式) → 修正轨迹
  → 落点预测
```

## 六、风险与局限性

### 6.1 3-5 米距离的精度限制

| 因素 | 影响 | 量化 |
|------|------|------|
| 像素分辨率 | 3m 距离下，1 像素 ≈ 1.6mm；5m 距离下，1 像素 ≈ 2.6mm | 杆头位置精度 ±2-5mm |
| 运动模糊 | 杆头速度 100mph 时，1/240s 曝光 → 模糊长度 ≈ 186mm | 需要运动模糊分析补偿 |
| 深度信息缺失 | 2D 视频无法直接获取深度 | SwingPlaneCorrector 可部分补偿 |
| LiDAR 范围 | iPhone LiDAR 有效范围 ~5m，3-5m 在边界 | 深度精度 ±1-3cm |
| 杆头速度精度 | 2D 追踪 + 3D 修正后，估计精度 ±5-10% | 球速误差 ±5-15 mph |

### 6.2 旋转率无法直接测量

- 旋转率对弹道影响巨大（倒旋决定高度，侧旋决定弯曲）
- 普通视频无法测量旋转率（需要 Doppler 雷达）
- **缓解方案**：球杆类型查表 + 杆头速度修正 + 杆面角度推断
- **精度预期**：旋转率估算误差 ±20-30%，导致落点距离误差 ±10-15%

### 6.3 简化模型 vs 真实弹道

| 简化 | 影响 | 严重度 |
|------|------|--------|
| 忽略 Magnus 效应 | 弹道高度和距离偏差 5-15% | 高 |
| 忽略风力 | 侧风 10mph 可偏移 10-20 码 | 高 |
| 固定阻力系数 | 实际 Cd 随速度变化（Reynolds 数效应） | 低 |
| 忽略球的变形 | 击球瞬间球变形影响初始旋转 | 极低 |
| 忽略地面效应 | 球接近地面时升力增加 | 极低 |

### 6.4 环境修正公式的已知问题

| 问题 | 来源 | 影响 |
|------|------|------|
| ClubUp 风速修正代码与注释矛盾 | ClubUp 分析文档 7.1 节 | 风速修正方向可能错误 |
| ClubUp 海拔系数偏小（1%/300m vs 行业 2%/305m） | ClubUp 分析文档 7.1 节 | 高海拔修正不足 |
| ClubUp 温度修正用固定值而非百分比 | ClubUp 分析文档 7.1 节 | 长距离修正不足 |
| 建议：在物理模型中直接调整空气密度 | 本文 3.6 节 | 比百分比修正更准确 |

### 6.5 数据依赖风险

| 依赖 | 当前状态 | 缓解方案 |
|------|---------|---------|
| 球杆类型识别 | 需用户手动选择或视频识别 | 可从挥杆特征（速度、平面角度）推断 |
| 天气数据 | 需 OpenWeather API | 可离线使用默认值 |
