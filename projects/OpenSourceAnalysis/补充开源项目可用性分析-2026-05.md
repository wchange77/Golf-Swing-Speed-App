# 补充开源项目可用性分析（golf-clip / GolfShotTracer / TrackNet / OpenTrace）

> 日期：2026-05-12
> 目标：补充分析用户指定 GitHub 参考项目，判断哪些部分可用于本仓库的 iPhone 高尔夫测速、球轨迹叠加、数据采集与回放分析链路。
> 核对方式：已通过 GitHub API 核对仓库元数据，并拉取源码到 `/private/tmp` 临时目录阅读关键文件；本报告不把第三方源码写入仓库。

## 一、结论

这批新增参考中，**最高优先级是 `carnhy/tracknetv5-golf`、`Hyvok/GolfTracer` 和既有 `elicoon/golf-clip`**。`tracknetv5-golf` 提供了面向高尔夫球的 TrackNet 热图检测、候选关联、主动学习挖难例和训练数据准备链路，尤其适合“iPhone 采集 → Mac 离线/近实时处理 → 回写 sidecar”的方案。`Hyvok/GolfTracer` 提供了“音频击球定位 → 相机运动稳定化 → 人工标注 → 鲁棒样条拟合 → 逐帧反投影渲染”的完整后处理闭环，适合回放分析和轨迹叠加验证；`golf-clip` 已有击球音频检测、球原点估计、Bezier 轨迹和视频导出思路，适合迁移到 iOS 原生实现。

`jonibek95/GolfShotTracer` 有 YOLOv5 球检测权重和一个带阻力/Magnus 的物理弹道原型，但工程上更像 notebook/YOLOv5 fork，建议只抽取“参数表 + 物理公式 + 可视化流程”做对照，不直接移植代码。`MaxenceMottard/GolfShotTracer-iOS` 是 SwiftUI + CoreML 逐帧检测原型，已归档，价值在 Vision/CoreML 调用方式和阈值暴露。`SangerZ/android-shot-tracer` 目前主要是 Android/CameraX/Compose 产品骨架，README 描述了 OpenCV/Room 等目标，但源码中算法尚未落地，暂不作为核心算法参考。

`Gi-gigi/TrackNetV6` 和 `jewbetcha/opentrace` 适合作为二级参考。TrackNetV6 展示了更复杂的 U-Net/Transformer 风格热图模型和视频推理 demo，但仓库下载过程中多次 partial transfer，只能基于 GitHub raw/API 阅读核心文本，后续必须完整拉取后复核。OpenTrace 更偏产品化手工轨迹工具，价值在浏览器端手动标点、TrackMan 风格三次 Bezier 轨迹、远端渲染和模型转换脚本，不应作为测速算法依据。

## 三、逐项目可用部分

### 3.1 golf-clip（既有重点参考）

可用部分：

- 音频击球检测：1-8 kHz 带通、瞬态检测、多特征评分、25 秒去重窗口，可迁移到 `AVAudioEngine + Accelerate/vDSP`。
- 球原点估计：人体检测、杆身线段、杆头颜色/区域综合评分，可与当前 Vision 骨架和点击追踪结合。
- Bezier 弹道：低成本生成社交分享型轨迹线，适合回放 UI 预览。
- 轨迹渲染：多层线条、辉光、颜色渐变，可迁移到 Core Graphics 或 Metal。
- Kalman/光流/模板匹配思路：可作为 `GolfAnalysisKit/Tracking` 现有管线的补充策略。

建议落点：

- `AppleOSDatasetCollectorApp`：在录制/回放时自动标记 `impact_timestamp` 和候选击球帧。
- `GolfBallDetectionApp`：先用 Bezier 做可视化预览，再用物理模型替代距离预测。
- `GolfAnalysisKit`：补一个纯 Swift 的 `ImpactAudioDetector`，参数先沿用 golf-clip 的频段与评分权重，之后用真机数据校准。

### 3.2 jonibek95/GolfShotTracer

源码观察：

- `README.md` 描述流程为 YOLOv5 检测球、估计初速/角度、模拟 3D 弹道并叠加到视频。
- `mathcalc.py` 包含阻力、Magnus、重力、旋转衰减等公式；默认常量包括空气密度 `1.225 kg/m^3`、球质量 `0.0453 kg`、球半径 `0.042672 m`、阻力系数初值 `0.205`。
- 仓库主体包含完整 YOLOv5 工程、`best.pt` 权重、演示视频和 notebook；核心高尔夫逻辑集中在 `mathcalc.py` 与 notebook 中。

可用部分：

- 物理弹道参数结构：`ballspeed / launchangle / spinrate / side spin / shape angle` 这组输入适合作为本项目 `TrajectoryPhysicsModel` 的外部参数契约。
- mph 到 m/s、rpm 到 rad/s 的换算逻辑可直接作为测试用例输入参考。
- OpenCV 叠加路径适合验证可视化效果，但 iOS 端应改为 Core Graphics/Metal。
- `best.pt` 可作为临时对照模型，但不能视为生产模型来源，必须重新核对训练集和授权。

不建议直接复用：

- YOLOv5 fork 体量大，和本仓库 `tools/train_ball_detector` 的轻量训练/导出路线重复。
- `mathcalc.py` 使用全局可变参数，测试隔离性弱；公式可以借鉴，代码不宜直接移植。
- README 中仓库名和 clone 地址存在 `Golf_Trajectory` / `GolfShotTracer` 不一致，维护规范一般。

### 3.3 MaxenceMottard/GolfShotTracer-iOS

源码观察：

- 单文件原型集中在 `Golf Shot Tracer/ContentView.swift`。
- 使用 `PhotosPicker` 选择视频，`AVAssetImageGenerator` 按 `nominalFrameRate × duration` 生成所有帧。
- 每帧用 `VNCoreMLRequest` 调用 `GolfBallTracking.mlmodel`，通过 `VNDetectedObjectObservation` 保存检测框。
- `confidenceThreshold = 0.15`、`iouThreshold = 0.1` 作为可调参数，但 UI 中被 `.hidden()` 隐藏。

可用部分：

- Vision/CoreML 调用路径清晰，适合做最小可验证的离线视频球检测 demo。
- `requestedTimeToleranceBefore/After = .zero` 对逐帧取图很关键，可用于回放分析的帧对齐验证。
- 阈值暴露方式可作为调参 UI 的参考，尤其适合 DatasetCollectorApp 的模型回放页。

风险与限制：

- 仓库已归档，代码停留在原型级；没有追踪、速度计算、轨迹拟合或导出。
- 一次性生成全视频所有帧会带来内存风险；本项目应继续使用流式读取或分段处理。
- `UIImage.ciImage` 对某些 `UIImage(cgImage:)` 可能为空，本项目实现时应直接用 `CGImage`/`CVPixelBuffer` 走 Vision。

### 3.4 SangerZ/android-shot-tracer

源码观察：

- README 描述目标包括实时球追踪、距离/发射角/球速/旋转率分析、CameraX、OpenCV、Room。
- 实际源码目前主要是 `CameraScreen.kt` 和 `AnalysisScreen.kt`：CameraX 只绑定了 `Preview`，录制按钮仅切换 `isRecording` 状态；分析页使用硬编码 sample shots。
- 未看到 OpenCV 球检测、视频录制、速度计算、Room 数据库或轨迹渲染的实现。

可用部分：

- Android CameraX 的权限与预览骨架可给跨平台参考，但对 iOS 主链路帮助有限。
- 分析页的信息架构（距离、速度、高度、准确率）可作为结果卡片字段参考。

不建议投入：

- 当前没有可迁移算法；不应纳入测速精度链路。
- 若后续仓库继续开发，可重新核对 OpenCV 实现是否落地。

### 3.5 Hyvok/GolfTracer

源码观察：

- `README.md` 明确完整链路：音频检测击球帧、SuperPoint+LightGlue 预计算相机运动单应/相似变换、人工标注球和可选杆头、三次平滑样条拟合、逐帧反投影渲染。
- `audio.py` 使用高通 1 kHz、5 ms 包络、50 ms onset lookback、可信窗口 `[0.5s, duration-1s]`、峰值至少为中位数 5 倍，并补偿约 70 ms 音画延迟。
- `geometry.py` 用 SuperPoint/LightGlue 匹配相邻帧，`cv2.estimateAffinePartial2D` + RANSAC 估计相似变换，并以 impact frame 为锚点链式计算每帧到击球帧坐标系的变换。
- `fit.py` 将点击点变换到稳定坐标系后，用 `UnivariateSpline` 分别拟合 `x(t)`、`y(t)`，首尾点高权重锚定，并用 Tukey biweight 做两轮鲁棒重加权。
- `render.py` 将稳定坐标中的样条点通过 `inv(homography[i])` 投回每帧，支持球/杆两条轨迹、三层线条、速度或进度着色、原音频 remux。

可用部分：

- **相机运动稳定化**：这是手持或轻微晃动视频轨迹叠加的关键能力，适合加入回放分析工具链，先离线验证，再考虑 iOS 端轻量化。
- **人工标注闭环**：适合 DatasetCollectorApp 增加“轨迹校正/标注模式”，把用户点击点保存为 sidecar，作为训练和验证数据。
- **鲁棒样条拟合**：比全局二次/三次多项式更适合用户点击噪声，适合作为轨迹叠加的默认平滑器。
- **音画延迟补偿**：70 ms 不是固定真理，但“按距离补偿音频到达延迟”的概念必须进入本项目击球帧标注逻辑。
- **缓存 sidecar**：`.gt.npz` 的设计可映射为本仓库 JSON/NPZ sidecar，用于保存 homography、点击点、impact frame 和 fit metadata。

iOS 迁移策略：

- 短期：保持 Python 离线工具，用 DatasetCollectorApp 导出视频后，在 Mac 上生成标注/轨迹 sidecar，再导回数据平台。
- 中期：iOS 端实现轻量版本，使用 Vision 特征点或 Optical Flow 做帧间稳定化，避免 CUDA 依赖。
- 长期：若要端上高质量稳定化，可评估 Core ML 特征匹配模型或 Metal 加速，但不应阻塞 M1 真机数据采集。

### 3.6 carnhy/tracknetv5-golf

源码观察：

- `model.py` 是 TrackNet 风格模型，输入为连续 3 帧拼接后的 9 通道图像，输出球位置热图。
- `dataset.py`、`prepare_training_data.py`、`pack_training_data.py` 覆盖训练样本准备，可支撑从本项目视频和标注 sidecar 生成训练数据。
- `losses.py` 使用热图类损失，适合小目标球检测，避免只做 bbox 时小球像素占比过低的问题。
- `inference_pipeline_v4.py`、`candidate_tracking.py` 包含 Top-K 候选、运动差分特征、Viterbi/全局路径关联思路，可降低单帧误检对轨迹的影响。
- `v41_mining_selector.py`、`categorize_misses.py`、`error_analysis.py` 体现主动学习闭环：从失败样本中挖难例，再回流标注和训练。

可用部分：

- **Mac 离线球检测主线**：iPhone 只负责高帧率采集和 sidecar 元数据，Mac 上用 PyTorch/MPS/CUDA 跑 TrackNet 热图推理，结果回写 `ball_observations.json`。
- **3 帧时间上下文**：比单帧 YOLO 更适合高速小球，因为球在连续帧中的位移和运动模糊本身就是信号。
- **候选轨迹全局关联**：把每帧 Top-K 候选交给 Viterbi/动态规划，适合解决白球、杆头、草地高光之间的混淆。
- **主动学习数据闭环**：与 DatasetCollectorApp 的“待复核/合格/不合格”状态天然匹配，可把失败视频自动加入再标注队列。

建议落点：

- `tools/train_ball_detector`：新增 TrackNet 训练分支，输入来自 DatasetCollectorApp 导出的帧序列和标注点。
- `projects/DatasetCollectionPlatform`：增加 `ball_observations.json` 契约，记录每帧热图峰值、候选点、置信度、轨迹关联 ID。
- `AppleOSDatasetCollectorApp`：短期只提供导出和回放核验，不在手机上强行跑完整 TrackNet。

### 3.7 Gi-gigi/TrackNetV6

源码观察：

- Git clone 两次失败，错误为 GitHub partial transfer / early EOF；已通过 GitHub API/raw 读取 `README.md`、`TrackNet-main/models/TrackNetV6_Beta.py`、`TrackNet-main/demo.py`。
- `TrackNetV6_Beta.py` 是更复杂的热图网络，包含卷积编码/解码、跳连和注意力/Transformer 风格模块，目标仍是从视频帧预测球热图。
- `demo.py` 展示 OpenCV 视频读取、模型加载、逐帧推理、热图解析和轨迹可视化流程。

可用部分：

- 模型结构可作为 TrackNetV5 后续升级候选，尤其当本项目积累足够标注数据后，可比较 V5/V6 的小球召回率和误检率。
- demo 的视频推理和热图解析流程可作为 Mac 侧 CLI 原型参考。
- 如果最终模型较大，可保留 Mac 侧处理，不必强行 CoreML 端上。

风险与限制：

- 本次未能完整 clone，必须在网络稳定后完整拉取并核对 license、权重、训练脚本和依赖。
- V6 复杂度更高，未必优于 V5；没有本项目标注集前，不应提前替换主方案。
- 若使用第三方预训练权重，必须确认训练数据与授权，不能直接进入生产链路。

### 3.8 bsraigur/TrackNet-Data-Annotator

源码观察：

- 仓库核心为 `TrackNet_DataAnnotator.py`，使用 Tkinter + OpenCV 做逐帧标注。
- 功能定位是给 TrackNet 生成球中心点标签，适合小数据集启动阶段。
- 界面和数据结构较简单，优点是可快速使用，缺点是缺少 DatasetCollectorApp sidecar 适配。

可用部分：

- 可作为“Mac 标注器最低可行版本”的流程参考：加载视频、逐帧定位球心、保存坐标。
- 标注结果应映射为本项目统一 schema，而不是直接保留工具私有格式。
- 可借鉴键盘快捷键和逐帧浏览方式，用于 DatasetCollectorApp 回放页或独立 Mac 标注工具。

补充观察：

- 另一个 `MarinGtr/TrackNet-Annotator` 更接近本项目的 Mac 标注设想：Streamlit UI，支持 MPS/CUDA/CPU，先用 TrackNetV5 自动预标再人工修正。它不是本次点名主仓库，但建议作为标注器交互备选参考。

### 3.9 jewbetcha/opentrace

源码观察：

- `README.md` 定位为 OpenTrace golf tracer，MIT License，前端为 TypeScript/React，后端/渲染包含 Python 与 Modal。
- `src/components/ManualTracerCreator.tsx` 实现手工轨迹点创建，适合参考点击标点、拖拽修正、预览状态管理。
- `src/lib/trajectory.ts` 使用 TrackMan-style cubic Bezier 生成轨迹，面向视觉轨迹展示。
- `src/lib/tracer.ts` 管理轨迹点和样式，偏产品化叠加效果。
- `modal-backend/render.py` 使用远端渲染环境处理视频合成，`scripts/convert_model.py` 提供模型转换脚本骨架。

可用部分：

- **手工轨迹交互**：对 DatasetCollectorApp 回放页很有价值，可参考“用户点少量关键帧 → 自动生成平滑轨迹 → 可视化预览”的产品流。
- **视觉轨迹样式**：Bezier、渐变、拖尾、渲染导出适合社交分享型轨迹，不适合作为速度结论。
- **远端/Mac 渲染思想**：本项目可替换为本机 Mac worker，不需要依赖 Modal；iPhone 负责上传原视频和 sidecar。
- **模型转换脚本**：可作为未来 PyTorch → CoreML/ONNX 转换工具的目录结构参考。

不建议直接复用：

- Bezier 轨迹是视觉插值，不包含物理约束，不能用于 carry、球速、发射角等结论。
- Web/Modal 架构与本仓库 Apple 原生采集链路差异较大，建议只借鉴交互和渲染层。

## 四、对本仓库的合并建议

### 优先级 P0：不改主测速链路，先加验证工具

1. 先把 `Hyvok/GolfTracer`、`OpenTrace`、TrackNet 标注器的流程合并成离线标注/轨迹生成参考，产物写成 `trajectory_annotation.json` 或扩展现有 `label_candidates.json`。
2. 在 DatasetCollectorApp 回放页增加“点击球轨迹点”模式，输出 `(frame_index, x, y, target_type)`。
3. 在 `GolfAnalysisKit` 中补 `TrajectorySplineFitter`，输入点击点和帧号，输出每帧平滑轨迹点；先不依赖 CoreML。
4. 在 Mac 侧先做 TrackNetV5 推理 CLI，读取 iPhone 导出视频，输出每帧 Top-K 球候选和全局轨迹。

验收标准：

- 选取 5 段现有 240fps 视频，每段至少标注 20 个球点。
- 样条拟合残差中位数 < 5 px，首尾点误差 < 1 px。
- 回放轨迹在固定机位视频中无明显漂移；手持轻微晃动视频先允许标记为实验。

### 优先级 P1：音频击球检测参数统一

1. 以 golf-clip 和 Hyvok/GolfTracer 共同验证的频段为依据：先用 1 kHz 高通/1-8 kHz 带通做候选。
2. sidecar 中记录 `raw_audio_peak_time`、`latency_corrected_impact_time`、`impact_frame`、`confidence`、`latency_assumption_ms`。
3. 延迟补偿不要写死 70 ms，应由拍摄距离估算：`latency_ms = camera_ball_distance_m / 343 * 1000`，再叠加 detector peak offset。

验收标准：

- 至少 30 段真机挥杆视频，人工标注 impact frame 作为对照。
- 自动击球帧误差中位数 <= 3 帧（240fps 下约 12.5 ms）。
- 误差超过 8 帧的视频必须进入“需人工复核”队列。

### 优先级 P2：物理弹道模型对照

1. `jonibek95/GolfShotTracer` 的输入参数契约可用于补充测试：球速 mph、发射角、spin rpm、side spin rpm。
2. 当前 `GolfAnalysisKit/TrajectoryPhysicsModel` 已有 RK4 + Magnus 方向，应优先把参数表和单位换算测试补齐，而不是迁移 `mathcalc.py`。
3. Bezier 只用于视觉轨迹，不作为距离/速度结论来源。

验收标准：

- 单位换算测试覆盖 mph→m/s、rpm→rad/s、yards/feet/meters。
- 固定参数下轨迹最高点、飞行时间、carry 距离在可解释范围内，并写入验证记录。
- 与外部雷达/TrackMan sidecar 对比前，报告中必须标注“预测值，非实测”。

### 优先级 P3：TrackNet 训练与 Mac 离线处理

1. 以 `carnhy/tracknetv5-golf` 为第一候选训练路线，先不要直接上 TrackNetV6。
2. iPhone 端继续保持采集稳定性，导出原视频、相机元数据、点击标注、质量验证结果。
3. Mac 端增加 `tracknet_infer` / `tracknet_train` 两类工具，结果回写 sidecar 后再由 DatasetCollectorApp 浏览和复核。

验收标准：

- 用 20 段真机视频做初始标注集，每段至少标出起飞后 20-40 帧球心。
- TrackNetV5 在验证集上的可见球中心误差中位数 <= 6 px，漏检帧比例 <= 15%。
- 全局关联后的轨迹不能出现明显跳点；跳点帧必须输出到人工复核列表。
- Mac 侧处理产物必须可被本仓库导入工具重复读取，不能只停留在临时 notebook。

## 六、风险

- 新仓库 star/fork 数都很低，不能用社区热度证明可靠性；所有算法必须用本项目真机数据重新验证。
- `Hyvok/GolfTracer` 的稳定化依赖 CUDA、SuperPoint、LightGlue，不适合直接端上 iPhone；它是“离线参考链路”，不是移动端实现方案。
- `jonibek95/GolfShotTracer` 的物理模型存在简化项和全局状态，不能直接作为测速精度依据。
- `GolfShotTracer-iOS` 的逐帧取图方式可能造成大视频内存压力。
- `android-shot-tracer` 当前实现与 README 目标不一致，不能按 README 宣称能力评估算法成熟度。
- TrackNet 系列依赖标注数据质量；没有本项目真机标注集前，模型指标不能外推到实际测速场景。
- TrackNetV6 和 OpenTrace 本次均未完整 clone 成功，只能按 API/raw 文本分析；后续需要网络稳定后补一次完整源码复核。
- Mac 离线处理可以放宽 iPhone 算力限制，但会引入传输、任务排队、结果回写和版本追踪问题，sidecar 必须记录模型版本与处理环境。
- OpenTrace 的 Bezier/视觉轨迹不能作为速度、发射角、carry 的物理依据。
